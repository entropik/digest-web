## Lecture globale

Le Jour 99 est une journée de garde-fous.

Elle commence par des sujets très techniques : migration pnpm, guardrails
Fabric, runtime catalog des templates, refresh retryable. Puis elle bifurque
vers un problème beaucoup plus sensible : la base locale ne doit plus être
seedee au mauvais moment, surtout quand elle doit servir de miroir au VPS.

La leçon est rude mais utile : une commande de développement qui semblait
anodine peut détruire de la confiance produit si elle remplace des données
métier attendues.

## Base locale : ne plus confondre seed et miroir

Le commit `f94432e` est le signal le plus important du jour :

```text
chore: protect local VPS mirror from seed
```

Le contexte est simple et douloureux : le produit **Zine** et d'autres données
admin existent sur le VPS, mais peuvent disparaître localement si un seed ou un
reset traite la base de développement comme un terrain jetable.

Pour KEREDIT, ce n'est plus acceptable. Le local sert parfois de miroir de
diagnostic. Il doit donc être protege contre les commandes destructrices par
défaut.

La règle produit est claire :

```text
preserver les donnees admin/metier avant de reconstruire une base
```

Le seed reste utile pour démarrer une base vierge contrôlée. Il ne doit pas
être une réponse automatique à une base déjà vivante.

## Ce que cette journée laisse

Le Jour 99 prepare le Jour 100.

D'un cote, les garde-fous techniques protègent le socle : pnpm, Fabric,
runtime catalog, seed local. De l'autre, les panneaux commencent a être
tailles pour l'usage réel, pas pour montrer toutes les possibilités du moteur.

La suite logique est évidente : reprendre le remplissage carnet avec le même
état d'esprit. Garder la puissance interne, mais retirer le bruit visible.
