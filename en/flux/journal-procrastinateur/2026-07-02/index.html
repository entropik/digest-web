Jour 101 - Ne plus déployer à l'aveugle

Jour 101 du journal : petit resserrage du déploiement VPS autour du couple version + SHA, puis bump KEREDIT 0.9.52.

Horaires de session

  • Agent utilisé : Codex
  • Environnement principal : VS Code WSL, plugin Codex, repo local
  • Date couverte : jeudi 2 juillet 2026
  • Branche KEREDIT observée : dev
  • SHA de fin de séquence observe : c948df5 (chore: bump release to 0.9.52)
  • Version KEREDIT observée : 0.9.52
  • Temps minimal observe le 2 juillet : 13 min+ d’amplitude de commits (20:37 -> 20:50, hors conversation et vérification manuelle)
  • Temps cumulé :610h33+ (610h20+ au 1er juillet, + 13 min+ ce jour)

Lecture courte

Petite journée, mais utile.

Le fil du soir est le déploiement VPS : ne plus se contenter d’une version qui semble bonne si le SHA raconte autre chose. Le script manuel refuse maintenant plus clairement les cas dangereux : version locale inferieure au VPS, ou même version avec deux commits différents.

Les commits du jour sont resserres :

  • 77c3e79 - bump release 0.9.51 après le chantier remplissage carnet ;
  • 43131f3 - durcir le garde-fou de version du deploy VPS ;
  • c948df5 - bump release 0.9.52 pour rendre ce garde-fou deployable.

Ce n’est pas une grande évolution produit. C’est une hygiène de livraison : KEREDIT doit savoir exactement quel couple version + SHA est attendu avant de toucher le VPS.

Pour la suite

Le prochain deploy nominal devra rester sur le chemin simple :

validation locale -> push dev -> ./deploy/manual-vps-local.sh -> verification SHA servi

Le point de vigilance est toujours le même : ne pas laisser le local, origin/dev et le VPS raconter trois états différents du produit.
