## Treize jours plus tard, la chaîne PDF

Retour après 13 jours de pause. Un seul commit mais c'est un gros bloc : 6 fichiers, 871 lignes d'insertions. La pipeline de génération PDF est en place.

L'architecture est claire : le frontend demande un export, le backend cree un job BullMQ, le worker traite le job avec pdf-lib, et le PDF genere est stocke dans MinIO. Tout est asynchrone, le client peut continuer a éditer pendant la génération.

## Choisir le vecteur plutôt que le navigateur

Le choix de pdf-lib plutôt que Puppeteer/Chrome headless est delibere : on veut un rendu vectoriel précis, pas une capture d'écran. pdf-lib permet de placer les éléments avec une précision au point pres, ce qui est essentiel pour le print.

BullMQ + Redis est le bon choix pour un MVP : fiable, bien documente, dashboard Bull Board pour le debug.

## Repères : BullMQ, Redis et pdf-lib

- `BullMQ` — file de jobs basee sur Redis pour traiter des tâches en arrière-plan.
- `Redis` — base en mémoire très rapide, utile ici pour les files de jobs.
- `pdf-lib` — bibliothèque JavaScript de génération PDF avec placement précis des éléments.
- `MinIO` — stockage objet local compatible S3, pratique pour le dev et les tests.
