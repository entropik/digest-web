Jour 69 - Garder la bêta petite et la mémoire propre

Journée de consolidation documentaire : point Go/No-Go du 1er juin, formalisation du journal Codex, workflow poubelle et premiers audits archivés.

Le fil rouge a été simple : décider petit, documenter vrai, nettoyer sans détruire.

Point Go / No-Go du 1er juin

Le matin a commencé par un point de décision sur l’ouverture du 1er juin.

Le verdict reste volontairement prudent : go réduit, pas lancement large. Le bon périmètre est une bêta clients amis contrôlée, avec postcard comme produit prioritaire, WooCommerce comme panier/paiement, et KEREDIT comme autorité métier pour les quantités, formats et prix.

Les vérifications et documents relus allaient tous dans ce sens :

  • docs/produit/ouverture-beta-keredit-juin-2026.md ;
  • docs/produit/roadmap.md ;
  • le billet du 27 mai ;
  • état local dev propre ;
  • pnpm dev:status ;
  • pnpm typecheck ;
  • pnpm lint ;
  • checks publics sur l’API KEREDIT, le thème, la page produit OOBLIK et le manifeste du plugin.

Conclusion pratique : la bêta du 1er juin est crédible pour quelques personnes choisies, mais elle reste conditionnée au replay du parcours complet entre le 29 et le 31 mai :

produit OOBLIK -> éditeur KEREDIT -> prix -> panier Woo -> retour édition -> commande -> backoffice/support

Le warning React connu dans frontend/src/components/admin/UsersPage.tsx reste non bloquant, mais il ne doit pas disparaître de notre radar.

Journal et transition Codex

Le premier commit du jour a rendu explicite le nouveau mode de travail documentaire.

Ajouts principaux :

  • création de .codex-skills/blog/SKILL.md ;
  • ajout d’une note de transition docs/blog/transition-claude-codex-2026.md ;
  • enrichissement de l’index du blog avec les notes transverses ;
  • ajout de métadonnées aux anciens billets ;
  • mise à jour de docs/guides/commandes-dev.md, docs/HOME.md et BIBLIOTHEQUE.md.

L’objectif n’était pas de refaire l’histoire. C’était de rendre durable la manière dont le journal doit être tenu maintenant que Codex devient l’outil principal : billets datés, horaires observés, commits, validations, contexte humain quand il compte, et index maintenu.

C’est important pour reprendre demain sans fouiller dans des traces dispersées.

Workflow poubelle

Le deuxième commit a ajouté un workflow de nettoyage réversible.

Nouveautés :

  • création de .codex-skills/poubelle/SKILL.md ;
  • ajout du script .codex-skills/poubelle/scripts/audit-tmp.sh ;
  • création de poubelle/ ;
  • création de poubelle-historique.md ;
  • mise à jour de docs/HOME.md et BIBLIOTHEQUE.md.

La règle est volontairement saine : on ne supprime pas l’histoire du projet. On sort les fichiers obsolètes du chemin de lecture courant, on conserve leur emplacement relatif sous poubelle/, et on écrit pourquoi.

Le premier passage a déplacé deux anciens rapports docs/analyse/print-ooblik-20260330-* vers :

poubelle/docs/analyse/

Ces fichiers n’étaient plus des surfaces de travail actives. Les garder dans l’arborescence principale donnait du bruit à chaque exploration documentaire.

Ce que cette journée change vraiment

La bêta n’est pas plus large qu’hier. Et c’est justement le point.

On a clarifié que le bon geste n’est pas d’ouvrir davantage, mais de rendre la reprise et l’audit plus fiables :

  • le verdict bêta est borné ;
  • le journal à un mode d’emploi versionné ;
  • la transition Claude Code -> Codex est documentée ;
  • les nettoyages futurs ont un protocole ;
  • les vieux artefacts peuvent sortir du chemin sans disparaître.

Ce n’est pas le genre de journée qui impressionne dans une démo. C’est le genre de journée qui évite de perdre deux heures dans trois semaines à se demander pourquoi un vieux rapport où une vieille note contredit l’état courant.

Vérifications

Vérifications relevées pendant la journée :

  • pnpm typecheck : OK ;

Pour les commits documentaires, le risque principal n’est pas runtime. Il est plutôt dans la cohérence des chemins et dans l’indexation, d’où les mises à jour de docs/HOME.md, BIBLIOTHEQUE.md et docs/blog/_index.md.

Reprise demain

Priorités recommandées :

  1. rejouer le parcours bêta complet en conditions propres ;
  2. corriger ou assumer explicitement le warning UsersPage.tsx ;
  3. vérifier régénération PDF / correction support sur un vrai projet ;
  4. préparer le message court pour les clients amis ;
  5. utiliser le workflow poubelle seulement avec preuves, pas comme rangement esthétique.

La journée a été plus calme que celle du 27 mai, mais utile : le produit reste orienté bêta, et le dépôt commence à mieux porter sa propre mémoire.
