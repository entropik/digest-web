Ce soir, la fatigue est la vraie information de planning.
Pas une fatigue dramatique. Plutôt celle qui dit : on a assez avance pour ne pas forcer une troisième décision importante a minuit.
La journée était simple a formuler, moins simple a exécuter : **Krampouz devait cesser d'être le nom visible du produit**. Le nouveau nom est KEREDIT. Et pour une phase commerciale, ce genre de détail n'est pas cosmétique. C'est le contrat que l'on montre, le nom qui apparaît dans les exports, les headers, le plugin, les docs publiques, les interfaces et les traces client.

## Branche dédiée

C'était important, parce qu'un renommage global est vite trompeur. Il ressemble à une opération mécanique, mais il traverse presque toutes les couches :

- frontend ;

- headers ;
- types partages ;
- PDF/export ;
- WooCommerce ;

Garder ce chantier hors de `dev` permet de travailler proprement sans fragiliser la branche de référence.

## Le nom public devient KEREDIT

Le premier gros commit a aligne les surfaces visibles.

KEREDIT devient le nom produit et commercial dans :

- l'éditeur ;
- le backoffice ;
- les logs et messages visibles ;
- les noms de fichiers exportes ;
- le contrat projet/PDF ;
- les metadata serveur ;
- les docs principales ;
- le plugin WordPress ;
- la skill de release du plugin.

Les headers emis passent en `X-Keredit-*`.

Les cookies emis passent en `keredit_*`.

Les exports deviennent `keredit-*`.

Le payload public d'export/projet parle de `Keredit*`, avec un schéma `keredit-project`.

Ce n'est pas encore une purge totale du mot historique dans le repo. Et ce n'est pas souhaitable en une seule passe : le nom du monorepo, `@krampouz/shared`, des chemins VPS, des buckets, des bases de données et des tokens Tailwind restent des sujets techniques. Ils seront a traiter avec leur propre risque, pas dans un coup de balai confus.

La bonne règle posée aujourd'hui :

**plus de Krampouz en surface publique ou commerciale ; quelques restes techniques acceptes seulement s'ils sont inventaries.**

## Le plugin WordPress repart vraiment en KEREDIT

Le point de vigilance du soir a été le plugin.

Au départ, une compatibilité avait été gardee par prudence :

- ancien endpoint client ;
- anciennes options ;
- anciennes metas produit ;
- ancien hook AJAX ;
- fallback `context.krampouz`.

Puis la décision produit est tombee, et elle est saine : **l'ancien plugin était une version de test**. Il n'y a donc aucune raison de traîner une migration WordPress lourde pour un nom que l'on veut justement quitter.

Le plugin a donc été corrige plus franchement :

- source dans `wordpress-plugin/keredit-connector/` ;
- fichier principal `keredit-connector.php` ;
- slug `keredit-connector` ;
- text domain `keredit-connector` ;
- endpoint client `keredit-projects` uniquement ;
- options et metas `keredit_connector_*` uniquement ;
- classes PHP `Keredit_Connector_*` ;
- assets et handles `keredit-connector-*` ;
- update channel `https://updates.ooblik.com/keredit-connector/manifest.json` ;
- ZIP `keredit-connector-0.1.20.zip`.

Le plugin ne contient plus d'occurrence `krampouz`.

C'est une bonne coupe. Le backend peut encore accepter certains anciens headers ou cookies en compatibilité invisible, mais le plugin WordPress, lui, repart avec le bon nom.
