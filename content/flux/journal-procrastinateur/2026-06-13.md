## Conclusion courte

Le 13 juin n'est pas une journée de grands gestes éditeur. C'est une journée de bêta réelle.

Le connecteur WordPress apprend a parler aux testeurs : messages de validation, message manuel, historique d'envoi, trace des destinataires et code bêta. Le tableau de bord KEREDIT cote WooCommerce devient aussi plus lisible : au lieu de séparer produits et options, il regroupe la synchronisation autour d'une question simple pour l'atelier : qu'est-ce qui vient de KEREDIT, qu'est-ce qui est visible dans WooCommerce, et quoi relancer si les données ne sont pas à jour ?

En parallèle, l'observabilité avance. OpenReplay n'est plus seulement branche : il devient un outil de lecture de bêta, avec SMTP documente, dashboard `beta KEREDIT`, événements frontend plus riches et guide d'audit mis à jour.

## Connecteur KEREDIT : parler aux testeurs bêta

Le commit `2e87d67` pousse le plugin KEREDIT jusqu'à la version **0.1.49**.

La bêta n'a pas seulement besoin d'un formulaire d'inscription. Elle a besoin d'un petit cycle de relation :

- validation manuelle d'un testeur ;
- email d'approbation explicatif ;
- message personnalisable avec le lien du produit carte postale ;
- code bêta `betacoco` injecte dans les messages ;
- message manuel aux testeurs valides ;
- confirmation avant envoi ;
- historique des envois avec destinataires et résultat.

C'est une brique très atelier : peu spectaculaire, mais essentielle pour ne pas ouvrir la bêta comme une simple liste d'emails. On commence à avoir un vrai canal d'accompagnement.

Les artefacts locaux montrent aussi des ZIP plugin produits entre **0.1.46** et **0.1.50** pendant la matinée. Pour ce billet, je ne declare pas la publication WordPress comme reverifiee : je documente les traces locales et les commits, pas l'état public du canal de mise à jour.

## Tableau de bord WooCommerce : synchronisation au bon endroit

Le commit `e374141` passe le plugin en **0.1.50**.

Le tableau de bord admin KEREDIT abandonne la séparation un peu technique entre `Produits` et `Options & formats`. à la place, il introduit un onglet **Synchronisation**.

Le sens produit est meilleur :

- KEREDIT reste la source de vérité des formats, options et quantités ;
- WooCommerce affiche et vend, mais ne redevient pas l'autorité métier ;
- chaque produit lie montre son `Product ID`, son template, son état de synchronisation, ses formats, options, quantités et restrictions Woo ;
- les actions utiles sont dans la même ligne : `Synchroniser`, `Modifier`, `Voir`.

C'est exactement le type d'écran dont on aura besoin pendant une bêta accompagnée : pas un backoffice générique, mais un panneau de contrôle assez lisible pour comprendre rapidement pourquoi un produit WooCommerce ne reflete pas encore la configuration KEREDIT attendue.

## OpenReplay : rendre l'audit exploitable

Le commit `1dfe94c` documente le SMTP OpenReplay sur `[serveur de production]`.

Le point important est pragmatique : le reset de mot de passe et les emails applicatifs OpenReplay passent par Fastmail en **587 STARTTLS**. Les ports `25`, `465` et assimilés peuvent piéger l'exploitation sur Hetzner. Le guide note les fichiers a maintenir sur le VPS, sans mettre les secrets dans Git :

- `~/openreplay/scripts/docker-compose/docker-envs/chalice.env` ;
- `~/openreplay/scripts/docker-compose/docker-envs/alerts.env`.

Le commit `a49a9de`, cree le 14 juin mais date dans le changelog au **2026-06-13**, ferme le paquet observabilité commence la veille.

Il ajoute le dashboard OpenReplay **`beta KEREDIT`** comme point d'entrée pour suivre ce que le client a vraiment vécu : sessions, utilisateurs uniques, erreurs JS, pages vues, requêtes 4xx/5xx, requêtes lentes et parcours utilisateurs.

Il enrichit aussi les événements frontend :

- reprise projet avec `project_resume` ;
- autosave plus explicite, avec durée, poids de payload, pages, éléments et références d'assets ;
- ouverture et envoi du retour bêta avec `bug_report_opened` et `bug_report_submitted` ;
- rapports automatiques d'erreur JS visibles dans la même logique d'audit.

La doc ajoute un piège d'exploitation important : après recreation de `chalice`, nginx OpenReplay peut garder une ancienne IP interne. Si l'UI OpenReplay affiche une erreur de récupération de données, il faut redemarrer `nginx-openreplay` avant de supposer que l'ingestion ou le tracker sont casses.

## Décision de clôture

La journée dit quelque chose d'important sur la phase actuelle de KEREDIT.

Le produit n'a plus seulement besoin que l'éditeur fonctionne. Il a besoin d'un entourage bêta : un plugin qui sait guider les testeurs, un WooCommerce qui ne masque pas la source de vérité KEREDIT, et une observabilité qui permet de revoir une vraie session client sans deviner.

GOF reste le futur forge PDF et le compagnon atelier, mais le 13 juin ne laisse pas de trace de code de son cote. Le travail utile est ailleurs : rendre l'ouverture bêta pilotable, visible, et un peu moins dépendante de la mémoire du moment.
