Administration and management via Chrome

The Digest is transitioning from a static archive to a proprietary curation system featuring administration, a Chrome extension and atomic publishing. Fifteen commits and thirty successful GitHub Actions runs have implemented this new workflow.

Requests and discussions

The following decisions were explicitly clarified during the conversation:

  • launch via the Chrome icon and a configurable shortcut.
  • A compact, pre-filled form and quick registration.
  • A private queue allowing users to select 10, 20 links or more.
  • Publication of a single Digest for the selected batch.
  • Use restricted to the owner only.
  • Title, category, summary and at least one tag are required for publication.
  • Suggested date and title; editable introduction and SEO description.
  • Categories and titles sorted alphabetically.
  • Blocked if the date already has a Digest.
  • Digest metadata can be edited after publication.
  • Tracking through to GitHub Actions validation and deployment to production.
  • Unlisted release on the Chrome Web Store with automatic updates.

Preparation for the Web Store then focused on the extension’s stable ID, the package, the icon, the screenshots, the description, the permission justifications and the privacy policy. The submission moved to ‘pending review’ status.

Decisions

  • Hugo remains the public site. admin-service is the sole backend.
  • The extension never communicates directly with GitHub.
  • Incomplete drafts are permitted, but their publication is blocked.
  • The taxonomy comes exclusively from the existing catalogue.
  • Private, local, authenticated or sensitive URLs are not permitted.
  • An active duplicate reopens the draft. A published link redirects to its administration page.
  • The catalogue and archive are written in a single commit.
  • Publication is idempotent and retries once following a GitHub conflict.
  • Private notes and selections never leave the private area.
  • The server only accepts the exact origin of the Web Store extension.
  • The extension uses Manifest V3, WXT and TypeScript without React.

Implementation

Viewing and history

Week 15 of 2017 has been added. The home page now features filters by date, random selection and favourites. Navigation and the archives have been improved. Broken links can point to a Wayback Machine archive whilst retaining their original URL.

Administration

The proprietary service adds Better Auth, the GitHub App, visibility modification and the /admin interface. Public deletion is deliberately discreet and separate from ordinary actions. A port conflict is resolved prior to deployment.

Curation and publication

SQLite stores drafts and publications. The APIs cover taxonomy options, CRUD, preview, publication, links and edits.

Publishing revalidates all data on the server side, enforces unique dates, creates stable UUIDs, writes two files per commit and follows SHA-related workflows. Shared fixtures align TypeScript and Python normalisation.

Extension and Chrome Web Store

The extension captures the URL, title, canonical, meta description and selection following an explicit action. Permissions are limited to activeTab, scripting and https://digest.ooblik.com/*.

The Web Store ID used is nlejcccmpbajpoaknlecegkpgdegiflf. Icons and promotional visuals are generated and stored at browser-extension/store-assets/. The public page /confidentialite/ describes the voluntary collection of data, its limited use and the permissions required. A link to this page is placed in the footer after ‘Admin’.

Operation

Two successive patches have improved the PM2 restart process when changing releases or when a previously stopped process needs to be recreated.

Validation and deployment

Prior to submission, the tests and type checks for the administration and the extension are passed, as are the catalogue checks and the Hugo build. The catalogue now contains 3,979 consistent links and 835 editions.

The workflows Validate and Deploy production are followed for changes to the extension, privacy policy and footer. The public result is checked after the CloudPanel handover.

The Chrome Web Store submission is now pending review. Google states that most reviews take a few days, but that they may take several weeks. A reminder is scheduled for 17 August 2026 to contact support if the status has not changed.

Firefox Extension

On 2 September 2026, the same framework became an official, signed Firefox extension. The blog post ‘Curation Comes to Firefox’ documents the adaptation to Manifest V2, AMO validation, the installation of version 1.5.0 and its testing in the live browser.
