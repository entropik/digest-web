Day 129 – Wrapping up the building sites

Day 129 of the diary: the Codex isolation workflow began on 9 August and was finally committed, without a pull request or a release on dev.

Session timetables

  • Tool used: Codex
  • Primary environment: Mac, worktreedépôt local krampouz-worktree-workflow
  • Date covered: Saturday 15 August 2026
  • Branch: chore/worktree-chantier-workflow
  • Trace observed: single commit 42f5a576 at 18:17 CEST; the changes themselves are dated 9 August
  • Minimum time observed: definite one-off intervention; duration cannot be quantified from this single commit
  • Publication status: branch pushed and still retained, with no pull request and not merged into dev as at 20 August
  • Minimum cumulative time since the start of the log: approximately 841h37+; no additional duration has been invented for the one-off commit on the 15th

Quick read

The project opened on 9 August has finally been committed. It adds the worktree-chantier skill, strengthens the deployment procedure and enshrines in the repository instructions a rule that has become necessary: a proper project is carried out on a dedicated branch and in a dedicated worktree.

The commit contains 261 lines added to the skills, guides and documentation maps. However, one should not claim that six days’ work were carried out on 15 August. The mtimes and the creation of the worktree link most of the writing to the 9th; the only evidence of work on that day is its Git commit at 6.17 pm.

A commit that is not yet a release

The work is preserved on the remote, but no PR links it to dev. This distinction matters for the log: a commit is not a release, and a pushed branch is not a rule actually shared by the product.

This discrepancy also says something about the pace. A procedure created to reduce mental load remains open for almost a week itself. This is not a technical incident; it is an early sign that the ability to finish off small outstanding tasks is beginning to wane.
