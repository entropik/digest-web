# 2026-08-16 — Publication progressive et environnement WSL

## Résumé

L’administration passe d’un parcours en deux boutons à une publication en une
seule action. Une progression compacte montre les états réels du serveur et
reprend automatiquement après un rechargement, un retour sur l’onglet ou une
erreur réseau transitoire. Le dépôt local a aussi été réaligné sur GitHub et
normalisé pour éviter le bruit de fins de ligne entre Windows et WSL.

## Demandes et échanges

- Remplacer la validation manuelle préalable par un parcours de publication
  plus simple.
- Afficher une petite barre animée afin de rendre l’attente compréhensible.
- Vérifier le reste du code local, puis aligner la copie WSL sur GitHub sans
  perdre d’éventuelles modifications.

## Décisions

- Garder tous les contrôles dans `CurationService.publish()` : le bouton
  d’aperçu était redondant, pas une barrière de sécurité.
- Représenter quatre étapes serveur plutôt qu’un faux pourcentage : préparation,
  validation, déploiement et mise en ligne.
- Respecter `prefers-reduced-motion` et accompagner chaque état d’un texte ; la
  couleur et l’animation ne portent jamais seules l’information.
- Conserver un seul temporisateur de suivi, relancer après une erreur transitoire
  et reprendre la publication active la plus récente au chargement.
- Imposer LF et déclarer les formats binaires dans `.gitattributes`. Les anciens
  écarts locaux restent récupérables dans des stashes datés du 16 août.

## Réalisation

- Action dynamique `Publier le lien` ou `Publier les N liens`, désactivée sans
  sélection.
- Suppression du bouton, de la route et de la méthode d’aperçu de publication.
- Progression accessible à quatre segments, animation discrète et alternative
  statique en réduction des mouvements.
- Reprise automatique du suivi et lien `Voir l’édition` après confirmation de la
  présence publique.
- Aperçu local capable de simuler les transitions de publication.
- Tests de contrat ajoutés pour l’action, la progression et le polling.
- Documentation du parcours et des précautions Windows/WSL mise à jour.

## Validation et déploiement

- `npm test` dans `admin-service/` : 39 tests réussis.
- `npm run build` dans `admin-service/` : compilation TypeScript réussie.
- `npm run typecheck`, `npm test` et `npm run build` dans
  `browser-extension/` : 70 tests réussis et extension construite.
- Les contrôles de catalogue, d’URL, d’archives et de cohérence passent sur
  3 992 liens et 836 éditions.
- Hugo Extended 0.164.0 construit le site de production avec succès.
- L’aperçu local renvoie successivement `validating`, `deploying` puis `live` ;
  son rendu desktop a été contrôlé et approuvé dans le navigateur Codex.
- Le déploiement est demandé dans ce chantier ; son résultat sera vérifié après
  fusion sur `main`.
