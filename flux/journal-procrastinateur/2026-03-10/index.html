Du prototype au produit administrable

Journée dense : 8 commits qui couvrent un spectre énorme. On passe du prototype a quelque chose qui ressemble à un produit.

D’abord l’infra : Docker test stack avec résolution du package @krampouz/shared, corrections de build (tsc références, Prisma, Redis). Puis la stabilisation du flux atelier (éditeur) — 10 fichiers touchés pour corriger le parcours de base.

Ensuite le gros morceau : centralisation de la résolution tenant (6 fichiers, nettoyage de l’ancien code), remplacement des placeholders admin par de vraies pages (14 fichiers, 750 lignes), et l’implémentation du workflow postcard v1 (16 fichiers, 611 lignes).

La journée finit avec la gestion des produits et templates admin (2060 lignes!) et l’expansion de la gestion des calques dans les templates (703 lignes).

Docker, tenants et cartes postales

  • Stack Docker de test fonctionnelle
  • Résolution @krampouz/shared dans Docker
  • Flux atelier stabilise
  • Résolution tenant centralisée
  • Pages admin réelles (plus de placeholders)
  • Workflow postcard v1 complet
  • CRUD produits et templates admin
  • Gestion des calques templates

Les secrets ne vivent pas dans l’image

Docker a été le premier mur. La résolution de @krampouz/shared dans un conteneur est un classique pnpm monorepo : le workspace protocol ne fonctionne pas comme en local. Il a fallu externaliser les secrets hardcodes aussi.

La centralisation tenant était nécessaire : le code de résolution était eparpille dans plusieurs fichiers.

Un gros commit exige une grosse relecture

2060 lignes pour l’admin produits/templates en un commit, c’est le genre de chose que Claude Code rend possible mais qui demande une relecture attentive. Le workflow postcard v1 est un jalon important : c’est la première fois qu’un produit concret traverse tout le stack.

Le produit devient enfin manipulable

Énorme bond en avant. On passe de “socle technique” a “produit utilisable” en une journée.

Les fondations de l’administration

  • Résolution tenant centralisée (6 fichiers)
  • Admin produits/templates (11 fichiers, 2060 lignes)
  • Workflow postcard v1 (16 fichiers)

Documenter avant la production

Documentation massive et workflow production. Le 11 mars sera une journée docs.

Repères : Docker, tenant et CRUD

  • Docker — technologie de conteneurs pour lancer l’application dans un environnement reproductible.
  • tenant — espace logique d’un client ou d’une organisation dans une architecture multi-tenant.
  • CRUD — create, read, update, delete : les quatre opérations de base sur des données.
  • monorepo — dépôt unique contenant plusieurs applications ou packages.
