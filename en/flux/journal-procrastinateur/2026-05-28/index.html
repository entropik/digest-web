1 June Go/No-Go decision

The morning began with a decision-making meeting regarding the 1 June launch.

The verdict remains deliberately cautious: a limited go, not a full-scale launch. The appropriate scope is a controlled beta for friends and clients, with postcard as the priority product, WooCommerce as the shopping basket and payment system, and KEREDIT as the business authority for quantities, formats and prices.

The checks and reviewed documents all pointed in this direction:

  • docs/produit/ouverture-beta-keredit-juin-2026.md ;
  • docs/produit/roadmap.md ;
  • the post dated 27 May;
  • dev’s local status was clean;
  • pnpm dev:status ;
  • pnpm typecheck ;
  • pnpm lint ;
  • public checks on the KEREDIT API, the theme, the OOBLIK product page and the plugin manifest.

Practical conclusion: the 1 June beta is credible for a select few, but it remains conditional upon the full user journey being re-run between 29 and 31 May:

produit OOBLIK -> éditeur KEREDIT -> prix -> panier Woo -> retour édition -> commande -> backoffice/support

The known React warning in frontend/src/components/admin/UsersPage.tsx remains non-blocking, but we must keep an eye on it.

Codex log and transition

Today’s first commit has made the new approach to documentation explicit.

Main additions:

  • creation of .codex-skills/blog/SKILL.md;
  • addition of a transition note to docs/blog/transition-claude-codex-2026.md;
  • enrichment of the blog index with cross-cutting notes;
  • metadata added to older posts;
  • updating docs/guides/commandes-dev.md, docs/HOME.md and BIBLIOTHEQUE.md.

The aim was not to rewrite history. It was to ensure the long-term sustainability of how the log should be maintained now that Codex is becoming the primary tool: dated entries, recorded timings, commits, validations, human context where relevant, and a maintained index.

This is important so that we can pick up where we left off tomorrow without having to trawl through scattered records.

Trash workflow

The second commit added a reversible clean-up workflow.

New features:

  • creation of .codex-skills/poubelle/SKILL.md;
  • addition of the `.codex-skills/poubelle/scripts/audit-tmp.sh` script;
  • creation of `poubelle/`;
  • creation of poubelle-historique.md;
  • updated docs/HOME.md and BIBLIOTHEQUE.md.

The rule is deliberately conservative: we do not delete the project’s history. We remove obsolete files from the current read path, retain their relative location under poubelle/, and record the reason why.

The first pass moved two old reports from docs/analyse/print-ooblik-20260330-* to:

poubelle/docs/analyse/

These files were no longer active workspaces. Keeping them in the main directory structure introduced clutter every time the documentation was browsed.

What this update really changes

The beta is no broader than it was yesterday. And that is precisely the point.

We’ve made it clear that the right approach isn’t to open things up further, but to make recovery and auditing more reliable:

  • the beta verdict is bounded;
  • the log has a versioned user guide;
  • the transition from Claude Code to Codex is documented;
  • future clean-ups follow a protocol;
  • old artefacts can be moved out of the way without disappearing.

This isn’t the sort of day that makes an impression in a demo. It’s the sort of day that saves you from wasting two hours in three weeks’ time wondering why an old report or a note contradicts the current status.
