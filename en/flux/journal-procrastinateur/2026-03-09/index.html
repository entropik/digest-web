Intégration WooCommerce : ajout au panier, webhook, UI checkout.

WooCommerce entre dans l’atelier

Retour après 15 jours. Deux commits qui posent l’intégration WooCommerce : ajout au panier, webhook entrant, et UI de checkout. 7 fichiers, 773 lignes. C’est la première connexion entre l’éditeur et le monde e-commerce.

Le flux est simple : le client personnalise sa carte dans l’éditeur, clique “ajouter au panier”, ça envoie un webhook vers WooCommerce qui cree l’article avec les métadonnées du projet Krampouz. Le panier et le paiement restent entièrement cote WooCommerce.

Du webhook au panier

  • Route d’ajout au panier Krampouz -> WooCommerce
  • Réception de webhooks WooCommerce
  • UI de checkout dans l’éditeur
  • Première PR mergée (#8) depuis le 9 février

Garder le commerce à la périphérie

La décision architecturale est claire : WooCommerce est un adaptateur, pas le cœur. On garde le contrat de données générique. Si demain on passe a Shopify ou à un front custom, seul l’adaptateur change.

Le raccourci nécessaire, pas le nouveau cœur

L’intégration WooCommerce est un mal nécessaire pour un premier lancement. C’est la solution la plus rapide pour avoir un tunnel de commande fonctionnel sans tout construire from scratch.

L’éditeur sait désormais vendre

Les briques s’assemblent : éditeur + PDF + e-commerce. Il manque l’infrastructure de production (Docker) et l’admin réel.

Le raccord WooCommerce

  • Routes webhook WooCommerce dans le backend
  • UI checkout dans le frontend

Conteneuriser puis administrer

Sprint massif en vue : Docker, admin, postcard v1, tout le 10 mars.

Repères : webhook, panier et pull request

  • WooCommerce — extension e-commerce de WordPress, utilisée ici comme adaptateur boutique.
  • webhook — appel HTTP automatique envoye par un service à un autre quand un evenement se produit.
  • PR — pull request : proposition de changement revue avant merge dans main.
  • CMS — système de gestion de contenu ou de boutique, branche ici autour de Krampouz.
