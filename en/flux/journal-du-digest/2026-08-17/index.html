Stricter editorial measures and LinkedIn screenshots

Common editorial actions are now accessible via each link to the owner. LinkedIn screenshots now feature a graphical collapse option and Chromium-based navigation protected against private networks. Eleven commits consolidate the whole system and restore the Windows environment to working order.

Requests and discussions

This summary has been compiled from the commits and their tests:

  • align the owner actions with the relevant links.
  • correct the display of bookmarks when the list is filtered.
  • No longer rely on a remote favicon that is missing or cached.
  • Ensure that when a link is shared, the image is genuinely specific to its destination.
  • Retain a usable image when the remote screenshot fails.
  • Audit and then harden the automated browser’s network perimeter.
  • Preserve the end of long LinkedIn texts and release all interrupted connections.

Decisions

  • Administrative actions remain server-side and restricted to the owning session, even when they appear in public lists.
  • A missing favicon uses an explicit local asset. Domain exceptions are versioned data and their cache is invalidated along with the other assets.
  • A link image prioritises a screenshot of the first screen, converted to black and white and overlaid with the title, domain and coral ink.
  • A site failure produces a typographic map specific to the link, never the generic banner for that edition.
  • Application-level URL validation is coupled with a pinned DNS resolution at the Chromium transport layer.
  • Streams, persistent media and connections not required for a static capture are blocked. Pending tunnels are limited and terminated along with their client.
  • When a LinkedIn text needs to be shortened, its conclusion and link are preserved.

Implementation

Administration and viewing

Link details display the options to edit, view and share when the owner is logged in. List filtering ensures no favourite remains in an inconsistent visual state. A demonstration resource is hidden in accordance with the editorial retention policy.

Resilient favicons

A local fallback replaces unavailable icons. A table of known domains allows this fallback to be selected directly, and the asset’s URL follows the site’s versioning to prevent an old response from remaining in the cache.

Link-specific images

The service opens the destination’s first screen in Chromium, disables animations, crops the image to 1200 × 627, converts it to black and white, then adds an OOBLIK banner. The result is named based on the link’s identifier and content, written atomically and stored in the shared directory. An action allows you to force its regeneration.

If navigation fails, a deterministic typographic SVG is rendered as a PNG containing the resource’s title and domain.

Network boundary and LinkedIn robustness

The main destination and each sub-resource are checked. A local proxy resolves each public host once, caches its address and connects Chromium directly to that address. Local networks, private addresses, unexpected protocols, non-standard ports and persistent resources are rejected.

The latest patches limit the buffer of a pending HTTPS tunnel, close the upstream connection as soon as the browser disconnects, and prevent a long LinkedIn text from losing its conclusion during normalisation.

Windows environment

Following the discontinuation of WSL for local development, the two directories ` node_modules` have been recreated on Windows to replace the native Linux binaries for Sharp, Rollup and other build tools. The README now specifies that switching between Windows, WSL and Linux requires this reinstallation and that node_modules must never be shared.

The extension audit also updates two transitive development dependencies, brace-expansion and nanoid, without changing the direct dependencies or the extension’s behaviour.

Validation and deployment

  • The changes are accompanied by tests covering admin actions, favicons, fallback rendering, Chromium capture, DNS pinning, buffer limits and socket closure.
  • The eleven functional changes were merged into main via pull requests nos. 44 to 52 whilst the work was being carried out on a dedicated branch.
  • The footer version is updated with the functional fixes up to v1.6.4, then to v1.6.5 for Windows dependency maintenance.
  • On Windows, all 80 admin tests and 70 extension tests pass. Type checking, both builds and the npm audits no longer report any errors.
