Fabric.js oublie les propriétés reconstruites

Le “piège du rebuild Fabric” est une complication non documentée de Fabric.js. Quand on change de page ou qu’on force un re-render, Fabric détruit et recree les objets. Les propriétés custom (crop offset, zoom level, rotation interne) disparaissent. Il faut un système de persistance parallèle dans le store Zustand.

La rotation centrée a été plus complexe que prévu : quand l’image dans le cadre est croppee ET pivotee, les transformations matricielles s’accumulent dans un ordre précis. Inverser deux transformations = image mal placée.

Le premier geste vraiment intuitif

C’est la première journée ou le bloc photo “fait ce qu’on attend”. Les handles ont un comportement intuitif : coin = resize homothétique, bord = recadrage, centre = déplacement image. C’est satisfaisant après 3 jours de combat.

Le piège rebuild Fabric est le genre de problème qui ne figure dans aucune documentation. On le découvre uniquement en usage réel. C’est documenté maintenant pour ne plus y retomber.

Le bloc fonctionne, le poli peut commencer

Le bloc photo est fonctionnel. Il reste le polish (barre d’outils, flip, reset cadrage) et les filtres image.

Repères : crop, pan et zoom

  • crop — recadrage d’une image à l’intérieur de son cadre.
  • pan — déplacement du contenu visible à l’intérieur d’un cadre.
  • zoom — niveau d’agrandissement du contenu dans un cadre ou sur le canvas.
  • Zustand — bibliothèque légère de store front pour garder l’état de l’éditeur.
