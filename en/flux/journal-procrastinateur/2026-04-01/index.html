Terminer la photo sans perdre l’alignement

17 commits. Journée marathon qui couvre trois axes en parallèle : la finition du bloc photo, les filtres image, et le snapping magnétique.

Ça commence par le raffinement de la barre d’actions photo et la restauration du format initial du cadre. Puis l’unification des toolbars photo (306 lignes de reorg). Le flip image traverse tout le stack (éditeur + PDF). Le crop overlay est corrigé pour les blocs pivotes, et le resize live arrive dans Fabric.

Ensuite, un virage vers les filtres : panneau d’enhancement basique (11 fichiers, 398 lignes), guide docs, assets design. Puis les filtres V2 avec presets d’intensité et un set noir et blanc (559 lignes). Et CLAHE (Contrast Limited Adaptive Histogram Equalization) pour le contrôle de clarté — un algo sérieux pour un éditeur grand public.

La journée finit par le snapping magnétique : alignement des blocs entre eux avec des guides visuels. 4 fichiers, 216 lignes pour la première passe. Puis pause — le snapping est mis de cote pour être repris proprement le lendemain.

Retournement, cadres, filtres et snapping

  • Flip image (éditeur + PDF)
  • Photo frame controls (reset cadrage, remplir/adapter)
  • Resize live pendant le drag Fabric
  • Crop overlay corrige pour les rotations
  • Panneau filtres image (luminosité, contraste, saturation)
  • Filtres presets avec intensité ajustable
  • Set noir et blanc (5 presets)
  • CLAHE clarity control
  • Snapping magnétique première passe

La rotation complique chaque découpe

Le crop overlay avec rotation a été un casse-tête géométrique. Quand le bloc est pivote, les handles de crop doivent suivre la rotation — mais les coordonnées du crop sont dans le référentiel local du bloc, pas dans le référentiel du canvas. Il faut transformer les coordonnées à chaque interaction.

Le CLAHE est peut-être overkill pour un éditeur de cartes postales, mais c’est un differentiel de qualité percu : les photos apparaissent plus nettes sans effort de l’utilisateur.

Le snapping a été pause en fin de journée. La première approche marchait mais créait du jitter : le handler object:moving de Fabric appelait setState React à chaque pixel de déplacement, ce qui déclenchait des re-renders en cascade. Il faudra un module dédié avec manipulation DOM directe.

Productivité élevée, dispersion possible

17 commits sur 3 axes différents, c’est un signe de dispersion ? Ou de productivité ? Avec Claude Code, on peut basculer d’un sujet à l’autre rapidement. Le risque c’est de laisser des chantiers a moitié finis. Le snapping mis en pause illustre bien ce risque.

Les filtres image sont un “wow factor” pour la bêta. Un testeur qui voit ses photos s’améliorer automatiquement est plus impressionne que par 100 optimisations de pipeline invisibles.

La photo presque close, le texte en vue

Le bloc photo est presque complet. Les filtres sont un bonus. Le snapping est commencé mais pas fini. Le texte n’est pas encore touché — c’est le prochain gros morceau.

Repères : CLAHE, snapping et DOM

  • CLAHE — algorithme d’amélioration locale du contraste pour rendre une photo plus lisible.
  • snapping — aimantation d’un élément sur des guides, bords ou autres objets.
  • DOM — structure HTML vivante de la page, manipulée par le navigateur et JavaScript.
  • Fabric.js — bibliothèque canvas qui sert de moteur d’édition visuelle dans Krampouz.
