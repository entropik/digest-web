Jour 53 - KEREDIT prend son nom

Journée de bascule de marque : création de la branche dev-keredit, remplacement des surfaces publiques Krampouz par KEREDIT, plugin WordPress renomme proprement, et inventaire des derniers restes techniques.

Horaires de session

  • Agent utilisé : Codex, transition depuis Claude Code
  • Branche de départ : dev
  • Branche de travail créée : dev-keredit
  • SHA de départ du chantier : f13de7a (feat: harden keredit connector flow)
  • Dernier SHA pousse avant clôture : 0c305f2 (fix: make wordpress plugin keredit-only)
  • Version applicative locale : 0.6.26
  • Version plugin WordPress : 0.1.20
  • Commits du jour sur dev-keredit : 2
  • Objectif du jour : ouvrir le chantier de renommage sans salir dev, puis nettoyer les surfaces publiques pour repartir commercialement sur KEREDIT Ce soir, la fatigue est la vraie information de planning. Pas une fatigue dramatique. Plutôt celle qui dit : on a assez avance pour ne pas forcer une troisième décision importante a minuit. La journée était simple a formuler, moins simple a exécuter : Krampouz devait cesser d’être le nom visible du produit. Le nouveau nom est KEREDIT. Et pour une phase commerciale, ce genre de détail n’est pas cosmétique. C’est le contrat que l’on montre, le nom qui apparaît dans les exports, les headers, le plugin, les docs publiques, les interfaces et les traces client.
  • Temps cumulé :257h+

Branche dédiée

Le premier geste a été de protéger dev.

Le chantier a démarre sur une branche spécifique :

  • vérification de l’état Git ;
  • création de dev-keredit depuis dev ;
  • push initial de la branche ;
  • travail par commits separes.

C’était important, parce qu’un renommage global est vite trompeur. Il ressemble à une opération mécanique, mais il traverse presque toutes les couches :

  • frontend ;
  • backend ;
  • cookies ;
  • headers ;
  • types partages ;
  • PDF/export ;
  • WooCommerce ;
  • plugin WordPress ;
  • docs ;
  • skills Codex ;
  • inventaire d’audit.

Garder ce chantier hors de dev permet de travailler proprement sans fragiliser la branche de référence.

Le nom public devient KEREDIT

Le premier gros commit a aligné les surfaces visibles.

KEREDIT devient le nom produit et commercial dans :

  • l’éditeur ;
  • le backoffice ;
  • les logs et messages visibles ;
  • les noms de fichiers exportes ;
  • le contrat projet/PDF ;
  • les metadata serveur ;
  • les docs principales ;
  • le plugin WordPress ;
  • la skill de release du plugin.

Les headers émis passent en X-Keredit-*.

Les cookies émis passent en keredit_*.

Les exports deviennent keredit-*.

Le payload public d’export/projet parle de Keredit*, avec un schéma keredit-project.

Ce n’est pas encore une purge totale du mot historique dans le repo. Et ce n’est pas souhaitable en une seule passe : le nom du monorepo, @krampouz/shared, des chemins VPS, des buckets, des bases de données et des tokens Tailwind restent des sujets techniques. Ils seront a traiter avec leur propre risque, pas dans un coup de balai confus.

La bonne règle posée aujourd’hui :

plus de Krampouz en surface publique ou commerciale ; quelques restes techniques acceptes seulement s’ils sont inventaries.

Le plugin WordPress repart vraiment en KEREDIT

Le point de vigilance du soir a été le plugin.

Au départ, une compatibilité avait été gardée par prudence :

  • ancien endpoint client ;
  • anciennes options ;
  • anciennes metas produit ;
  • ancien hook AJAX ;
  • fallback context.krampouz.

Puis la décision produit est tombée, et elle est saine : l’ancien plugin était une version de test. Il n’y a donc aucune raison de traîner une migration WordPress lourde pour un nom que l’on veut justement quitter.

Le plugin a donc été corrigé plus franchement :

  • source dans wordpress-plugin/keredit-connector/ ;
  • fichier principal keredit-connector.php ;
  • slug keredit-connector ;
  • text domain keredit-connector ;
  • endpoint client keredit-projects uniquement ;
  • options et metas keredit_connector_* uniquement ;
  • classes PHP Keredit_Connector_* ;
  • assets et handles keredit-connector-* ;
  • update channel https://updates.ooblik.com/keredit-connector/manifest.json ;
  • ZIP keredit-connector-0.1.20.zip.

Le plugin ne contient plus d’occurrence krampouz.

C’est une bonne coupe. Le backend peut encore accepter certains anciens headers ou cookies en compatibilité invisible, mais le plugin WordPress, lui, repart avec le bon nom.

Inventaire et dette acceptee

Un audit a été ajouté :

docs/audits/2026-05-12-keredit-renaming-inventory.md

Son rôle est simple : éviter une dette floue.

Les restes autorises sont classes :

  • imports et packages internes @krampouz/shared ;
  • nom technique du repo ;
  • chemins et noms infra existants ;
  • S3, DB, Compose, VPS ;
  • tokens Tailwind historiques ;
  • compatibilité backend invisible pour anciens cookies/headers.

Cela donne une base claire pour la suite. On ne dit pas “il reste des trucs”. On dit “il reste ces familles, avec ces raisons, et voici les prochaines passes”.

Vérifications

Checks effectues sur le premier lot :

  • git diff --check
  • pnpm --filter @krampouz/shared typecheck
  • pnpm typecheck
  • pnpm lint
  • pnpm plugin:lint
  • pnpm plugin:build
  • node .codex-skills/wp-plugin-release/scripts/prepare-manifest.mjs
  • pnpm build
  • audits rg sur Krampouz, KRAMPOUZ, krampouz

Le build complet passe. Le seul signal notable reste le warning Vite habituel sur des chunks lourds, déjà connu sur l’éditeur.

Après la correction plugin, un audit spécifique confirme :

rg "krampouz|Krampouz|KRAMPOUZ" wordpress-plugin .codex-skills/wp-plugin-release

Résultat : rien.

État final

État à la clôture :

  • branche dev-keredit créée et poussée ;
  • dev reste stable ;
  • surfaces publiques alignées sur KEREDIT ;
  • plugin WordPress renomme proprement ;
  • manifest plugin regenere avec checksum ;
  • docs principales et inventaire mis à jour ;
  • backend encore tolérant en lecture legacy la ou c’est invisible ;
  • aucun deploy VPS effectue ;
  • aucun publish live du plugin effectue.

Commits de la journée :

  • 42ee7f3 - feat: align public surfaces on keredit
  • 0c305f2 - fix: make wordpress plugin keredit-only

Le chantier n’est pas termine au sens “plus aucune occurrence technique”. Mais il est passé dans un état beaucoup plus sain : KEREDIT est maintenant le nom que l’on peut montrer.

Et ce soir, c’est suffisant.

La suite devra traiter les noms internes avec plus de méthode que de bravoure : package @krampouz/shared, tokens Tailwind, infra VPS, chemins de deploy, buckets et variables historiques. Pas tout en vrac. Pas à la fatigue.

Rideau.
