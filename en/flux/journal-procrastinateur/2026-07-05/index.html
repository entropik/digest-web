Day 104 – Streamlining photo imports

Day 104 of the diary: lighter upload confirmation, gradual Google Photos import, separate asset files and book folding guides.

Session timetable

  • Tool used: Codex
  • Main environment: VS Code WSL, Codex plugin, local repo
  • Date covered: Sunday 5 July 2026
  • KEREDIT branch observed: dev
  • SHA of observed sequence end: 6bb70ec6 (chore: bump beta deploy version to 0.10.3)
  • KEREDIT version observed: 0.10.3
  • Minimum time observed on 5 July: 10h38+ of commit duration (00:09 → 10:47, excluding conversations, tests and deployments)
  • Minimum cumulative time since the start of the log: approximately 628h50+ (618h12+ as at 4 July, + 10h38+)

Quick read

Today’s work focuses on improving the photo import experience: less blocking wait time, fewer mixed-up queues, and a more progressive workflow.

The first commits of the day streamline the upload confirmation and Google Photos import:

  • fcfbc21e / 995c3b3a prevent the upload confirmation from becoming a resource-intensive operation;
  • 5a35313b / f8df47bb make the Google Photos import progressive;
  • 0b03497d make the import retry-safe;
  • c10e7889 adjusts the hash expectations in the tests.

The commit 5d5c7c81 then separates the ‘preview’ and ‘print-ready’ workers. This is an important separation for the beta: an image must become visible quickly in the library without waiting for the full print pipeline to complete.

The end of the sequence involves two version bumps (0.10.2, then 0.10.3) and a fix for book fold guides (78db1787). The book product remains secondary to the postcard, but its features must not deteriorate whilst we are hardening the imports.

Looking ahead

The contract to be retained: uploaded followed by preview_ready is the visible path for the user; print_ready remains a production issue, not a reason to block publication.
