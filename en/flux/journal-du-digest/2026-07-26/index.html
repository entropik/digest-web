Requests and discussions

This section has been reconstructed from Git.

The identifiable functional requirement is simple: to be able to tag resources so they can be found again without turning the Digest into a multi-user application. The chosen solution avoids the need for authentication, user profiles and synchronisation.

The historical data is being restored in small batches, which allows us to monitor the metadata and gradually create new tag pages.

Decisions

  • Bookmarks are strictly local to the browser.
  • They are stored using the versioned key digest-favorites-v1 in localStorage.
  • If storage is unavailable, bookmarks remain usable during the session.
  • No bookmarks are sent to the server.

Implementation

Weeks 11, 12 and 14 add their archives, imports and taxonomies. The bookmarks feature is integrated into the main grid and the modal view, with accessible status and local persistence.

Validation and deployment

All eight GitHub Actions runs visible for the day were successful. Each import passes the catalogue consistency checks before the Hugo build.
