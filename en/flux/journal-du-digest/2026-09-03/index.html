/index 03 September 2026

A bilingual Digest, restored movements and cron admin

The Digest is preparing an English version, accessible via a discreet FR/GB selector, whilst continuing to work on its translation in batches. The ‘About’ tooltip adapts to narrow windows and accessibility changes, and the tags resume their behaviour after the page is refreshed. The Node environment for the admin cron is documented and aligned with Node 22.

Requests and discussions

  • Translate the entire interface and, gradually, the content, whilst keeping things simple using DeepL.
  • Prioritise the core of the site, the latest editions and the Procrastinator’s Journal.
  • Distinguish between the percentage of editorial content translated, the credit used, and the translations actually published.
  • Check the ‘About’ page and the titles visible in the English archives as a priority.
  • Report that the text tooltip and the automatic movement of tags have disappeared.
  • Diagnose the system settings and reproduce the conditions under which the issue occurs, without altering the machine’s preferences.
  • Explain why the public site and the administration panel displayed different versions following a successful merge, then correct the relevant scheduled task.

Decisions

  • Retain the French URLs and generate the English pages at /en/.
  • Maintain the usernames, original destinations and favourites common to both languages.
  • Set aside part of the credit for new content, without assuming a monthly renewal.
  • Preserve the French source files and display a ‘pending’ status when a translation is missing.
  • Keep historical documents in their original language and produce English versions of typographic posters.
  • Remove the arbitrary 900px threshold for mouse-over effects, without enabling this effect on touchscreens.
  • Stop displaying the prompt ‘plouf ?’ when mouse hover is disabled.
  • Comply with prefers-reduced-motion and its changes without reloading.
  • Maintain a single tag loop and restart it during successive page reloads.
  • Also provide a URL with a fingerprint to the liquid text script to refresh its cache after publication.
  • Limit the correction to the admin command environment, without altering the public site’s schedule.
  • Retain the pre-existing system task and flag it as a duplicate rather than implicitly deleting another configuration.
  • Distinguish between the success of GitHub checks and the version actually served by each of the two components.

Implementation

  • Export of the public manifest via Hugo and generation of the English pages via a content adapter.
  • SQLite file, field hashes, retention of manual corrections and daily history.
  • ‘Translations’ tab with coverage, credits, rework requests and a distinction between preparation and publication.
  • Actual translation of static pages and the ten most recent titles and descriptions of editions.
  • Deferred initialisation and resetting of the fluid text according to the current preference.
  • Pausing and resuming the tag explorer on pagehide and pageshow.
  • Three regression tests running the actual scripts and a reproducible Chromium check.
  • Preparation of version 1.27.0, followed by alignment of the public and administrative versions on 1.27.4.
  • Diagnosis of installation failures for native dependencies under Node 20, explicit selection of Node 22 in the admin cron job, and documentation of the operational procedure.

Validation and deployment

  • Testing with a simulated API for rate limits, interruptions, priorities and publication errors.
  • Chrome checks of the selector, search, calendar and favourites on desktop and mobile devices.
  • Proofreading of a translated sample and local verification of the ‘About’ page.
  • Full local validation: testing of the admin panel and extension, editorial checks and bilingual build.
  • All three motion regression tests fail before correction and then pass.
  • Chromium checks at 1280, 834, 390 and 320 px: hover on desktop, tag movement, animation scaling, search and absence of horizontal overflow.
  • The rollback scenario is triggered by persistent browser events, as real-world browsing did not utilise the cache in the test environment.
  • Release authorised on 3 September via a pull request to main, the CI and public and administrative deployment procedures.
  • Node 22.23.1 and npm 10.9.8 verified in a minimal environment; confirmation of the next step in the cron logs and maintenance of health checks without restarting the service.

Next steps

  • Check the English pages and version 1.27.4 on both services following deployment.
  • The catch-up to 70 per cent remains pending explicit activation in the administration panel.
  • Reducing animations remains a priority, and no system preferences or local exceptions are enforced.
  • Consolidate the two admin schedules during a dedicated intervention, whilst retaining the existing safeguards and health checks.
