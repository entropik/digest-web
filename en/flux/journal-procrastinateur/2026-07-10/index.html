Jour 109 - Le contrat print traverse les deux dépôts

Jour 109 du journal : styles de polices, géométrie clipart et payload print alignés entre KEREDIT et GOF, puis migration P340 sécurisée.

Horaires de session

  • Agent utilisé : Codex
  • Environnement principal : VS Code WSL, plugin Codex, repos KEREDIT et GOF, candidate P340 documentée
  • Date couverte : vendredi 10 juillet 2026
  • Branches observées : dev dans KEREDIT et GOF
  • SHA KEREDIT de fin de séquence : a840461 (chore(release): bump keredit to 0.10.20)
  • SHA GOF de fin de séquence : 87336ed (fix: allow isolated GOF candidate deploys)
  • Versions observées : KEREDIT 0.10.20, GOF 0.2.12
  • Commits directs observés : 3 KEREDIT + 4 GOF
  • Temps minimal observe le 10 juillet : 8h01+ d’amplitude multi-dépôts (11:43 -> 19:44, hors tests machine, restauration et vérification atelier)
  • Temps cumulé :693h50+ (685h49+ au 9 juillet, + 8h01+)

Lecture courte

Le 10 juillet montre ce que veut dire maintenir deux dépôts sans fabriquer deux vérités. Les mêmes heures voient KEREDIT preciser le payload et GOF renforcer le writer qui le consomme.

La seconde partie de la journée quitte le rendu pour l’exploitation : deux machines portent encore le hostname [nom privé], donc la migration doit identifier le materiel autrement que par son nom Linux.

Les styles de police deviennent explicites

Dans KEREDIT, d349814 durcit le rendu des polices et la géométrie clipart. Le catalogue, le payload et les surfaces éditeur doivent transmettre assez d’information pour que GOF ne devine pas une variante.

Au même instant, c8f9d9d ajoute cote GOF la synthèse encadree des styles et les garde-fous de synchronisation. Les tests couvrent résolution, glyphes, writer et fixtures de contrats réels.

L’objectif n’est pas d’accepter silencieusement n’importe quel fallback. Il est de rendre explicite ce qui est exact, ce qui peut être synthétise dans la même famille et ce qui doit bloquer.

Le clipart cesse d’être une convention implicite

782854f aligne KEREDIT sur le contrat clipart rendu : rotation interne, retournement, couleur, fit et géométrie de contenu passent par les types, la validation, les builders et les tests.

18cc4d5 applique le même contrat dans GOF. Un champ persiste doit être rendu, signale comme non supporte ou explicitement ignore. Il ne doit plus changer de sens entre Fabric et le PDF.

La release KEREDIT atteint 0.10.20; GOF atteint 0.2.12.

La P340 devient une candidate identifiable

La forge historique et la ThinkStation P340 gardent volontairement le hostname gof. 9a6c831 introduit donc GOF_NODE_ID, un marqueur lie à la machine et des scripts qui refusent une cible inattendue.

La documentation de migration, le runbook, le plan d’implémentation et les tests d’exploitation sont ajoutés dans le même lot. La candidate peut être auditee sans devenir par accident la forge primaire.

87336ed permet enfin les déploiements isoles sur la candidate. Le but est de tester le rendu et la capacité sans rejoindre la production Accurio ni confondre les deux environnements.

Pour la suite

La chaîne print est plus cohérente, mais la vitesse d’un PDF lourd reste liée au cœur GOF. Le prochain sujet n’est plus seulement quelle machine acheter : il faut aussi comprendre le parallélisme, le cache et la précompilation.
