Jour 42 — Masques et cadres passent du backoffice au canvas

La journée a transformé le chantier Masques/Cadres en vrai flux testable : import backoffice, catalogue front, erreurs d'upload lisibles, previews groupées, puis application bêta des masques luminance sur les blocs photo. Le PDF reste volontairement garde pour la validation finale.

Point de départ

Après plusieurs jours consacres au texte, la décision du jour a été de ne plus toucher au bloc texte et de basculer sur les assets décoratifs restants pour la bêta carte postale.

Le besoin initial semblait simple : reprendre la logique déjà construite pour les cliparts et l’appliquer aux masques et aux cadres. En pratique, il fallait fermer tout le chemin :

  • backoffice Masques et Cadres dans /admin/assets ;
  • import massif de PNG catalogue ;
  • tri, metadata, statut, tags, suppression ;
  • affichage dans le panneau Decorations cote éditeur ;
  • insertion ou application dans le canvas ;
  • persistance propre dans les projets.

Le cadrage produit est reste volontairement sobre : copier ce qui marche déjà pour les cliparts, éviter un nouveau moteur image, et garder l’alignement PDF comme point de validation finale plutôt que de le traiter dans la precipitation.

Backoffice assets

La première partie de la journée a été consacrée au backoffice.

Les onglets Masks et Frames ont été traduits et actives en Masques et Cadres. Le backoffice commun DecorativeAssetsPage reprend la logique catalogue : recherche, catégorie, statut, sélection multiple, action de masse, import, suppression protégée si l’asset est utilisé.

L’import a ensuite été durci par les tests réels.

Un premier problème était visuel : l’upload massif affichait plusieurs barres de progression par ligne, ce qui rendait un lot de 160 fichiers pénible a lire. L’UI a été simplifiée pour n’afficher qu’une progression globale, dans l’esprit du flux cliparts.

Un deuxième problème était diagnostique : 22 fichiers étaient en échec, mais le message ne disait pas pourquoi. Le backend renvoie maintenant des détails exploitables : type MIME declare, type détecte, signature du fichier, taille, types attendus. Ce n’est pas encore une analyse artistique du fichier, mais c’est suffisamment concret pour comprendre si le fichier n’est pas un PNG catalogue autorise.

Enfin, les previews ont été rendues moins bruyantes. L’ancien libellé apercu a regenerer était à la fois mal accentue et trop visible sur chaque asset. La logique est maintenant regroupée : les aperçus manquants sont traites en batch et l’interface évite de polluer chaque carte avec un état secondaire.

Catalogue front

Une fois l’import backoffice valide, le test dans l’éditeur a montré que les assets n’apparaissaient pas encore dans le panneau Decorations.

Le manque était normal : il existait un backoffice, mais pas encore de route catalogue front pour exposer les masques et cadres actifs à l’éditeur.

Le flux a donc été complété :

  • nouvelle route authentifiée /api/decorative-catalog/:kind ;
  • API frontend decorativeCatalog ;
  • affichage des masques et cadres dans les onglets Masques et Cadres du panneau Decorations ;
  • support du click et du drag depuis la bibliothèque ;
  • backfill groupe des aperçus manquants.

Vérification de clôture locale : le catalogue masques retourne 138 masques actifs et 0 preview en attente.

Le vrai sujet : un masque n’est pas un clipart

Le test visuel a ensuite clarifié le vrai comportement attendu.

Poser le PNG noir/blanc au-dessus de la photo n’est pas un masque. C’est juste une image décorative qui cache la page. L’effet voulu est celui des editeurs photo classiques : la partie blanche du PNG laisse passer la photo, la partie noire la masque.

La décision technique du jour :

  • un masque clique ou glisse ne cree pas un nouvel élément libre ;
  • il s’applique au bloc photo sélectionne, ou à la photo sous le point de drop ;
  • le bloc image persiste la référence maskAssetId ;
  • le rendu canvas utilise un masque luminance : blanc visible, noir transparent ;
  • l’alpha du PNG source est pris en compte ;
  • une action Retirer le masque apparaît dans la mini toolbar photo.

Ce choix garde le modèle simple : le masque appartient au bloc photo, il ne devient pas un nouveau type d’objet flottant. C’est plus cohérent pour l’utilisateur et plus sain pour la sauvegarde.

Persistance et protections

Le changement avait une conséquence importante : un masque applique à une photo devient une référence d’asset projet.

Les chemins backend ont donc été ajustes :

  • extractReferencedAssetIds inclut maintenant maskAssetId ;
  • la sauvegarde projet accepte les assets catalogue mask et frame actifs ;
  • l’historique éditeur traite les changements de masque comme une mutation asset ;
  • la suppression d’un asset utilise comme masque détache le masque au lieu de supprimer la photo entière.

C’est un détail discret, mais c’est exactement le genre de point qui évite une régression destructive plus tard.

Limite assumée

Le rendu canvas est maintenant aligne avec l’effet attendu pour le test manuel.

Le rendu PDF n’est pas encore aligné avec ce nouveau contrat de masque. C’est volontairement garde comme objectif de validation finale : avant de declarer les masques terminés, il faudra vérifier que le PDF applique le même masque que l’éditeur, sans inventer une convention différente.

La règle pour la suite est simple : si l’éditeur montre une photo masquée, le PDF doit produire le même résultat. Sinon, ce sera un bug de contrat éditeur/PDF, pas un simple détail d’export.

État de clôture

Le lot du jour laisse un chemin testable :

  1. importer des PNG masques/cadres en backoffice ;
  2. vérifier les erreurs d’upload quand un fichier est refusé ;
  3. retrouver les masques dans l’éditeur ;
  4. sélectionner une photo ;
  5. cliquer un masque ou le glisser sur la photo ;
  6. vérifier que le blanc laisse passer la photo et que le noir la masque ;
  7. retirer le masque depuis la mini toolbar.

La prochaine reprise naturelle sera une session de test manuel sur plusieurs formes de masques, puis seulement ensuite l’alignement PDF.
