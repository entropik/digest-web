Jour 23 — Le snapping devient un module

Extraction snapping en module dédié, bi-axis, manipulation DOM directe. Deploy Dockhand documente.

Sortir le magnétisme du canvas

6 commits. D’abord le fix des resets de state pour les contrôles image (lint). Puis la PR #18 merge le gros travail photo des derniers jours.

Le commit principal du jour : extraction du snapping dans un module dédié avec support bi-axe. 3 fichiers, 506 lignes ajoutées, 322 supprimées. Le snapping sort de EditorCanvas.tsx et vit dans frontend/src/lib/snapping.ts — fonctions pures, types dédiés, manipulation DOM directe pour les guides visuels.

Le reste : mise à jour des docs projet avec la référence au module snapping, documentation du workflow de déploiement Dockhand, nettoyage tsconfig, et recadrage du roadmap bêta postcard.

Un module dédié, biaxial et sans tremblement

  • Module snapping dédié (snapping.ts)
  • Support snap bi-axe (horizontal + vertical)
  • Manipulation DOM directe pendant le drag (pas de setState)
  • Guides visuels sans jitter
  • Documentation Dockhand deploy
  • Roadmap bêta postcard recadre

React faisait vibrer les repères

Le problème du jitter est résolu par un principe devenu règle du projet : pendant le drag, les guides visuels et l’overlay de sélection sont mis à jour par manipulation DOM directe, pas par setState React. Ça évite les re-renders et le lag perceptible.

Le module exporte des fonctions pures (getObjectBounds, collectSnapLines, findSnaps) sauf getObjectBounds qui dépend de Fabric. C’est un compromis acceptable — le couplage est minimal.

Le recadrage du roadmap bêta est une décision importante : on passe d’un objectif “mise en ligne publique” a “bêta fermée avec quelques testeurs”. Plus réaliste, plus actionable.

Extraire pour pouvoir enfin tester

Extraire le snapping dans un module propre plutôt que de le laisser dans le composant canvas, c’est le bon réflexe. Le coût est faible et le gain est réel : testabilite, lisibilité, reutilisabilite pour tous les types d’éléments (image, texte, forme).

Le recadrage bêta est sain. Mieux vaut une bêta fermée qui marche qu’un lancement public bancal.

Une bêta recentrée sur la carte postale

La section 6bis du roadmap est ajoutée : bêta fermée, scope postcard uniquement, pas de WooCommerce ni de tunnel commande. L’objectif est qu’un testeur fasse une belle carte sans assistance.
