Overall summary

Today’s work moves away slightly from the visible core of the editor to strengthen the tools surrounding it.

The photo log is still present with the ‘refill’ preview, but the main thread is now up and running: reducing noise, making feed testing easier, documenting upcoming editor projects, and hardening GOF in terms of security and performance.

It’s not the sort of day that yields a spectacular screenshot. It’s the sort of day that prevents the beta from becoming impossible to monitor.

KEREDIT: refill, lint and workshop command

Today’s KEREDIT commits:

  • 0aa6b31 - aligning the notebook refill preview;
  • 87d667d - restore a clean lint state;
  • a513692 - track the editor refactoring backlog;
  • 7051e75 - reduce beta observability noise;
  • a59e3a2 - added the `test-flux` command for the workshop pipeline;
  • 30ea669 - bump release 0.9.47;
  • e1d5676 - streamline the WooCommerce project recovery options.

The most important practical point is test-flux. A workshop pipeline cannot rely solely on unit tests or manual clicks. We need a command capable of replaying the WooCommerce -> KEREDIT -> GOF -> workshop flow in a reproducible manner.

The other useful point is the reduction in observability noise. Too many logs make the real signals invisible. In closed beta, we want to see the errors that change a decision, not every single system heartbeat.

WooCommerce: resuming without overloading

The WooCommerce project resumption selector has been streamlined.

This is not a cosmetic detail. In the e-commerce workflow, users often return after an interruption: an order link, a project already created, photos already present, and a decision to resume. If the resumption screen looks like a technical dashboard, trust declines.

The fix follows the same principle as the order form: less mental load, a clearer path.

GOF: security, cache and staging retention

GOF also saw significant changes that day:

  • f1341a8 - tightening access to artefacts and rendering;
  • 61e98a6 - limiting the cache buffer for PDF assets;
  • 43fdfff /e7bc345 - adding and then tightening the staging retention workflow;
  • 7adff60 - released GOF 0.1.85;
  • e38bf59 / 37b38da - added and then enlarged the GOF favicon.

The GOF hardening counts towards KEREDIT because GOF is not an annex. It is the artefacts forge: web PDFs, print PDFs, workshop files, operator verification. If GOF retains data for too long, exposes too much, or consumes too much cache space, the entire chain becomes vulnerable.

What this day leaves us with

The theme of the day is simple:

moins de bruit -> plus de diagnostic
plus de replay -> moins de superstition

KEREDIT is starting to have the tools needed to test an entire workshop workflow without having to mentally reconstruct everything every time an incident occurs. GOF is becoming stricter on security and more resource-efficient.

It’s not spectacular, but it’s exactly the sort of work that makes a beta version usable.
