Le fil de la journée

La veille avait rendu le partage public robuste. Aujourd’hui, le travail bascule vers une question plus commerciale : comment faire du partage un vrai livrable client, sans redonner au navigateur des URLs internes, sans confondre PDF web et PDF atelier, et sans rouvrir tous les risques de la forge PDF dans KEREDIT.

Le thème dominant est donc la frontière :

KEREDIT decide, vend, expose et protege.
GOF fabrique les artefacts optimises.
WooCommerce porte le panier et le paiement.

Cette phrase devient moins théorique qu’hier. Elle se retrouve dans le lecteur public, dans le contrat livre, dans le toggle admin PDF web, dans la configuration GOF, puis dans le chainon WooCommerce qui permet d’acheter le PDF web après une commande déjà passée.

Livre : séparer couverture atelier et lecture web

Le premier commit de la journée, fb88c2c, corrige une ambiguïté importante sur les produits livre / zine. Une couverture atelier a plat n’est pas une page de lecture. Pour l’atelier, la couverture reste un support technique. Pour le lecteur public, il faut présenter un objet lisible :

1re couverture
page blanche
cahier
page blanche finale
4e couverture

Le commit 1278567 prolonge cette logique dans le partage. Les zones de couverture sont remappees pour que la première et la quatrième de couverture soient extraites correctement depuis la couverture extérieure a plat. Les tests de layout livre, d’export payload et de preview encadrent ce contrat.

C’est exactement le genre de détail qui fait passer KEREDIT d’un éditeur de pages à un outil d’atelier : une structure correcte pour produire n’est pas toujours la structure correcte pour lire.

Lecteur public : du polish vers le produit

Une grande partie de la journée a aussi poli le lecteur public :

  • styles de navigation plus simples ;
  • table des matières visuelle ;
  • miniatures mieux alignées ;
  • couture centrale plus lisible ;
  • protection de la dernière page du cahier ;
  • respect des polices rich text dans l’aperçu public ;
  • modale de partage dans l’éditeur ;
  • action de copie du lien mieux alignée ;
  • toggle plus clair pour l’état de partage.

Ces commits ne sont pas tous sur le premier-parent final, mais ils expliquent le merge 5b11b22. Le lecteur n’est plus seulement une preuve technique de StPageFlip. Il devient une surface client : navigable, partageable, moins fragile, plus proche de l’objet imprime.

PDF web : vendre un livrable sans exposer GOF

Le gros saut fonctionnel du jour est le PDF web.

5b11b22 introduit les contrôles de livraison PDF web :

  • toggle PDF web dans Admin > Commandes ;
  • champ ProjectShare.pdf_web_enabled pour contrôler l’accès public ;
  • génération GOF web_share capable de porter un artefact web_preview_pdf ;
  • bouton de téléchargement dans le lecteur public quand le droit est actif ;
  • tests backend et frontend autour du partage et du preview.

0686895 corrige ensuite un point de sécurité et d’architecture : le navigateur client ne doit jamais recevoir l’URL GOF brute. Le téléchargement passe donc par KEREDIT :

/api/project-shares/:token/artifacts/web-pdf/download

KEREDIT vérifie le token, l’état du partage et le droit PDF web, puis recupere l’artefact GOF cote serveur et renvoie le PDF au client.

d7d2cfc corrige enfin l’origine des artefacts GOF : si un ancien artefact garde une URL LAN, KEREDIT sait la réécrire vers l’origine publique configurée avant de la télécharger. C’est un détail très concret, mais essentiel pour éviter le classique bug “ça marche depuis le réseau local, pas depuis le VPS”.

Roadmap : septembre remplace la bêta comme contrainte dure

Le commit a09ebbc, integre dans le merge du jour, ajoute docs/produit/roadmap-operationnelle-septembre-2026.md.

La contrainte y est beaucoup plus nette que les anciennes notes bêta :

le 30 septembre 2026, le contrat commercial Printbox doit pouvoir s’arrêter.

La bêta ne disparaît pas. Elle change de rôle. Elle n’est plus le but final, elle devient l’outil de réduction de risque avant migration commerciale.

La roadmap remet le sujet dans le bon ordre :

  1. vendre et reprendre des projets sur ooblik.com ;
  2. retrouver commandes, clients, fichiers, options et support ;
  3. distinguer produits autonomes et produits accompagnes ;
  4. préparer l’import clients Printbox ;
  5. ne pas promettre la migration éditable des anciens projets tant qu’elle n’est pas prouvée.

Cette clarification compte parce que la technique du jour, PDF web compris, ne sert pas a faire une belle démo. Elle sert à remplacer progressivement une dépendance commerciale réelle.

WooCommerce : vendre le PDF web avant et après commande

La fin de journée transforme le PDF web en vrai parcours commercial, pas seulement en override atelier.

Avant commande, le produit KEREDIT peut exposer l’option standard :

livrables-web = none | pdf_web

Le seed ajoute cette option au carnet classique, et le flux existant selected_options continue de porter le choix jusqu’au projet. Le partage garde ensuite la même règle : GOF ne reçoit web_preview_pdf que si KEREDIT a bien livrables-web=pdf_web.

Après commande, le plugin WordPress keredit-connector passe en 0.1.60 et ajoute une option de configuration Produit PDF web. Dans Mon compte > Projets, le bouton Ajouter le PDF web apparaît seulement pour un projet déjà commande, appartenant au client connecte, et sans droit PDF web actif.

Le panier WooCommerce reçoit alors un produit complémentaire avec deux metas cachées :

_keredit_project_id
_keredit_addon_type = pdf_web

Quand WooCommerce notifie KEREDIT après paiement, le backend vérifie le tenant, le projet, le fait que le projet a déjà une commande, et l’email du client. Si tout concorde, KEREDIT active Project.options["livrables-web"] = "pdf_web", met à jour ProjectShare.pdf_web_enabled si un partage existe déjà, puis redemande un rendu GOF web_share.

Comme ce code touche le plugin WordPress, il devra être traité comme une vraie release plugin. La partie code est préparée avec :

  • header plugin et constante KEREDIT_CONNECTOR_VERSION en 0.1.60 ;
  • changelog readme.txt ;
  • manifest.example.json aligne sur 0.1.60 ;
  • ZIP local keredit-connector-0.1.60.zip genere ;
  • checksum manifeste sha256:5131ba68bcca8df62aeb54444756c0beb2ff2676de54fc6484b1f63788e48136.

La publication effective sur updates.ooblik.com reste à faire au moment du deploy nominal, via le workflow plugin complet.
