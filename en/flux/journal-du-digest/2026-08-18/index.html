The LinkedIn feed: from false success to a visible post

LinkedIn visuals use a 1200 × 1200-pixel square. Real-world testing reveals the API’s false successes and leads to synchronising uploads, enabling reposting and simplifying retrieval. Seventeen commits bring both the site and the administration to `v1.8.6`.

Requests and discussions

  • Replace the rectangular LinkedIn poster with a true square that takes up more space in the feed.
  • Maintain the same behaviour for administration and for directly sharing a link.
  • Regenerate the square versions of all past posts.
  • Understand why a post accepted by the API results in ‘This post cannot be displayed’.
  • Allow a retry without silently creating a duplicate.
  • Close the modal at the right time and remove a second confirmation that has become superfluous.
  • Check whether the dark grey bands visible in the viewer are part of the image.

The final successful attempt results in a visible post with its square image. It confirms both the technical correction and the design choice.

Decisions

  • The Open Graph image remains at 1200 × 627. LinkedIn receives a dedicated file of 1200 × 1200.
  • Historical posts retain both formats. Future generations and backfills must maintain this pair going forward.
  • Screenshots specific to links are also composed as a square.
  • The dark grey bands at the top and bottom of the large LinkedIn viewer are accepted: they result from its container being taller than it is wide and must not be included or compensated for in the PNG.
  • The legacy Assets API is used in ‘SYNCHRONOUS_UPLOAD’ mode so that the creation of the post waits for the image to be processed.
  • A URL remains protected against duplicates. Republishing is only permitted via the explicit action ‘Repost if the post is inaccessible’.
  • This button already conveys a sufficiently clear intention. An additional confirmation box complicates the user journey without making it any more secure.

Implementation

Two formats for each edition

The generator produces a 1200 × 627 Open Graph poster and a 1200 × 1200 LinkedIn variant from the same deterministic identity. The 836 historical editions have been completed, and the backfill tools now maintain both outputs. The publication validator accepts the paths for these square variants.

Square for direct sharing

The screenshot of a link’s first screen is redrawn within a square canvas. The composer detects the PNG’s natural dimensions and displays the preview without imposing the old aspect ratio. The typographical fallback follows the same format.

From false success to synchronous upload

An initial attempt returns a LinkedIn URN and a ‘creation successful’ status, but the post is missing from the profile and its URL remains inaccessible. The cause is a race condition between the asynchronous processing of the asset and the creation of the post. The save operation now requires SYNCHRONOUS_UPLOAD. The request to publish is only sent once the upload has completed.

Retrieval without hidden duplicates

The URN from the false success had been cached, so a new attempt on the same URL would normally return ‘already published’. The interface then offers the option to republish, which removes this single association, re-establishes an atomic lock and executes the corrected workflow.

For an archive, the modal closes to reveal the result and its button on the page. When the message exists only within the modal, the modal remains open. The additional native confirmation has ultimately been removed.

Validation and deployment

  • The suite now has 114 successful tests, with checks dedicated to square images, synchronous uploads, deduplication, retries and the behaviour of modal windows.
  • The TypeScript build succeeds after each fix.
  • Pull requests 64 to 76 pass GitHub Actions validation. The main LinkedIn changes are delivered via PRs 70 to 76.
  • The public and admin versions are verified after deployment, up to v1.8.6, then the corresponding annotated Git tags are pushed.
  • The final test on LinkedIn produces a visible, properly formatted post that is correctly linked to its text and URL.
