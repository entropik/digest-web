Jour 9 — Package blog et nettoyage

Ajout d'un package blog au workspace pnpm, nettoyage du code mort.

  • Première trace git du jour : 08:50 CEST
  • Dernière trace git du jour : 08:50 CEST

Un blog apparaît entre deux nettoyages

Session courte : 2 commits. On ajoute un package blog au workspace pnpm (2719 lignes, principalement du boilerplate) et on nettoie le LeftPanel obsolète et les scripts dev.

Un package de plus, un panneau de moins

  • Package blog ajoute au monorepo avec pipeline CI
  • Suppression du LeftPanel obsolète (322 lignes supprimées)
  • Scripts dev durcis et docs mises à jour

La bonne idée arrivée au mauvais moment

Le package blog sera finalement retiré plus tard (voir jour 10). C’est un exemple de feature exploratoire : on essaie, on decide que ça ne rentre pas dans le scope du MVP, on enlève proprement.

Explorer sans confondre avec avancer

Parfois on construit quelque chose pour se rendre compte que ce n’est pas le bon moment. Le blog dans le monorepo ajoutait de la complexité au build sans être sur le chemin critique de la bêta postcard.

La maintenance reprend la priorité

Maintenance pure. Le chemin critique reste l’éditeur postcard.

Le blog éphémère et le panneau retiré

  • Package blog (ajoute puis retire dans les jours suivants)
  • Suppression LeftPanel obsolète

Réconcilier les branches

La grande harmonisation des branches.

Repères : monorepo, CI et MVP

  • monorepo — dépôt unique contenant plusieurs applications ou packages.
  • CI — intégration continue : vérification automatique du code à chaque push ou PR.
  • MVP — version minimale mais utilisable d’un produit, suffisante pour valider l’usage.
