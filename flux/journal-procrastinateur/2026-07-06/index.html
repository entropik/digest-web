Incident observabilité WooCommerce

L’alerte Grafana “Erreurs 5xx > 2%” n’a pas révélé une panne générale. Les probes VPS montraient un backend sain, et les compteurs concentraient les 500 sur POST /api/woocommerce/webhook.

Le diagnostic a remonté au webhook WooCommerce 13, actif sur ooblik.com, topic order.updated, URL KEREDIT woo_ooblik_live. Ce webhook est légitime : il relie les commandes WooCommerce a KEREDIT. Le bruit vient du ping natif WooCommerce deliver_ping(), qui envoie un corps non JSON du type webhook_id=13. KEREDIT attend un JSON de commande signe et répondait donc en 500 à ce ping. Les vrais webhooks de commande continuaient a passer.

Conclusion opérationnelle : pas d’incident backend global, mais une correction KEREDIT reste utile pour absorber ce ping en 200 ou en rejet contrôle, sans polluer les alertes 5xx.
