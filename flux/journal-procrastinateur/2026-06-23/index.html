Lecture globale

La journée n’est pas une journée de nouvelle fonctionnalité spectaculaire. Elle ressemble plutôt à un passage de peigne avant d’élargir le produit : chaque surface publique ou semi-publique qui avait été ouverte les jours precedents est resserree.

Le partage public avait pris beaucoup d’importance avec le lecteur web et le PDF web. Il devient donc une zone a traiter comme un produit expose :

  • le HTML public ne publie plus toute la structure projet brute ;
  • les assets originaux ne sont plus envoyés directement au partage ;
  • les URLs d’artefacts publics sont bornées ;
  • les liens peuvent expirer cote serveur ;
  • l’affichage dépend maintenant du produit.

Ce dernier point est important pour le métier : un carnet photo reste un objet multipage a feuilleter, une carte postale devient un recto/verso simple, et les produits non prevus pour le partage peuvent être bloques explicitement.

KEREDIT comme source de vérité produit

Le chantier share_display_mode clarifie une question produit apparue avec les cartes postales : tous les projets ne doivent pas être lus comme un livre.

Le contrat retenu est volontairement simple :

book        -> book_flip
postcard    -> simple_pages
autres      -> disabled par defaut

L’admin produit peut surcharger ce comportement. Le lecteur public consomme ensuite share_display.mode depuis les payloads publics, sans que WordPress devienne la source de vérité. C’est cohérent avec la règle actuelle : KEREDIT decide le projet, le produit, le partage et le droit d’accès ; WooCommerce reste la porte commerce.

Sécurité et exploitation

Le lot sécurité ferme aussi plusieurs risques de “petites valeurs par défaut” :

  • les routes Better Auth credentials passent par un rate-limit ;
  • les intégrations admin ne sont plus gerables hors rôle admin ;
  • les URLs retour WooCommerce sont validées ;
  • les sessions/debug storage ne gardent plus de secrets generiques ;
  • les couleurs et URLs images injectees dans les previews sont validées ;
  • les actions GitHub et permissions CI sont reduites ;
  • les images Docker doivent être taguees explicitement ;
  • LOG_ALL_REQUESTS n’est plus verbeux par défaut en production.

Ce n’est pas une garantie de sécurité globale, mais c’est le bon type de travail pour une bêta : retirer les expositions évitables avant d’ajouter du trafic client.

Chantier encore ouvert : panier WooCommerce

Au moment ou ce billet est rédige, un diff est encore ouvert sur le panier WooCommerce :

  • shared/src/schemas/woocommerce-launch.ts ajoute un payload updateWooCommerceCartProjectOptionsSchema ;
  • backend/src/routes/woocommerce.ts expose un endpoint /woocommerce/cart/project-options ;
  • backend/src/services/woocommerce-service.ts prépare la fusion des options modifiables, le recalcul KEREDIT et le retour d’un payload panier mis à jour ;
  • wordpress-plugin/keredit-connector/includes/class-cart-bridge.php commence à rendre des options éditables dans le panier WooCommerce et a les renvoyer a KEREDIT.

Ce chantier n’est donc pas note comme termine. Le bilan du jour le garde comme action en cours : il prolonge le PDF web et les options atelier dans le panier, mais il doit encore être validé, probablement accompagne d’une release plugin si le fichier WordPress reste dans le scope.
