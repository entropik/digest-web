État provisoire

La matinée commence par un détail visuel, puis remonte rapidement vers un vrai conflit de logique : ce qu’un template bloque pour le client ne doit pas rendre l’élément manipulable, mais ce que le client ajoute lui-même ne doit pas être fige par les restrictions globales du template.

Le symptôme est très concret : sur une carte postale, un asset de verso verrouille cote template laisse encore apparaître un cadre ou un mini-menu cote client ; puis, après correction, les cliparts ajoutes par le client deviennent a leur tour figes parce qu’ils heritent trop fortement des permissions du template.

Permissions template et éléments client

Le premier lot clarifie la différence entre mode template et mode client.

En mode template, l’admin doit pouvoir sélectionner un élément, même verrouille, pour régler sa géométrie et ses permissions. En mode client, c’est l’inverse : si l’élément n’a aucune action autorisée, il ne doit pas présenter de cadre manipulable ni de mini-menu.

Les commits du matin suivent cette ligne :

  • 39ce348 masque les contrôles d’assets verrouilles cote client ;
  • fd8e39a aligne les permissions d’affichage avec les interactions Fabric ;
  • 23c8c5f redonne des permissions locales explicites aux assets crees par le client ;
  • c2634b0 rend le correctif rétroactif pour les projets déjà sauvegardes.

Le point important est le dernier. Les anciens projets pouvaient contenir des cliparts ajoutes par le client sans editorPermissions locales. Ils heritaient donc encore des restrictions globales du template au rechargement. La correction compare les éléments du projet avec ceux du template source : un élément présent dans le projet mais absent du template est traité comme un élément cree par le client.

Cette restauration se fait au chargement, sans mutation directe de la base. La prochaine sauvegarde du projet peut ensuite persister l’état corrige.

La documentation reste volontairement factuelle. Le point à conserver pour la suite : les permissions locales d’un élément client peuvent prendre le dessus sur les permissions globales du template, mais les anciens champs locked, movable, editable et deletable restent des garde-fous bas niveau.
