Jour 99 - Protege la base, simplifie les panneaux

Journée de migration pnpm, guardrails Fabric, runtime templates, protection anti-seed local/VPS et simplification du panneau Templates.

Lecture globale

Le Jour 99 est une journée de garde-fous.

Elle commence par des sujets très techniques : migration pnpm, guardrails Fabric, runtime catalog des templates, refresh retryable. Puis elle bifurque vers un problème beaucoup plus sensible : la base locale ne doit plus être seedée au mauvais moment, surtout quand elle doit servir de miroir au VPS.

La leçon est rude mais utile : une commande de développement qui semblait anodine peut détruire de la confiance produit si elle remplace des données métier attendues.

Tooling et contrats éditeur

Les premiers commits structurent la base technique :

  • d6f1fe1 - migrer le workspace vers pnpm 11 ;
  • ba08cb7 - ajouter des guardrails Fabric ;
  • d16d4bc - documenter le certificat auto-signe Accurio ;
  • 6685ce8 - restaurer une baseline shared book ;
  • 0cb69ff - rafraîchir le runtime catalog de mise en page photo ;
  • 2466fa1 - garder le refresh de layouts retryable.

Ces changements sont moins visibles qu’un panneau UI, mais ils stabilisent les zones ou les régressions coûtent cher : Fabric, les templates runtime, la compatibilité outil, et les intégrations atelier.

Base locale : ne plus confondre seed et miroir

Le commit f94432e est le signal le plus important du jour :

chore: protect local VPS mirror from seed

Le contexte est simple et douloureux : le produit Zine et d’autres données admin existent sur le VPS, mais peuvent disparaître localement si un seed ou un reset traite la base de développement comme un terrain jetable.

Pour KEREDIT, ce n’est plus acceptable. Le local sert parfois de miroir de diagnostic. Il doit donc être protégé contre les commandes destructrices par défaut.

La règle produit est claire :

preserver les donnees admin/metier avant de reconstruire une base

Le seed reste utile pour démarrer une base vierge contrôlée. Il ne doit pas être une réponse automatique à une base déjà vivante.

Panneau Templates : simplifier ce qui se voit

La fin de journée revient à l’UX :

  • 93262cb - compacter le résume de sélection templates ;
  • f3f9a07 - simplifier les détails de sélection ;
  • 1c7b05b - clarifier le texte d’aide ;
  • 468ae1b - compacter le sélecteur nombre de photos ;
  • 8d49c8e - corriger la densité de la grille ;
  • 9001a08 - ajouter une respiration de scrollbar.

Le panneau Templates sert de référence pour le remplissage carnet. Ses contrôles doivent être compréhensibles, cohérents, et suffisamment denses pour travailler vite.

La journée confirme un principe qui va dominer le lendemain :

si une option existe pour le moteur, elle n'a pas forcement a exister pour le client

Ce que cette journée laisse

Le Jour 99 prépare le Jour 100.

D’un cote, les garde-fous techniques protègent le socle : pnpm, Fabric, runtime catalog, seed local. De l’autre, les panneaux commencent a être tailles pour l’usage réel, pas pour montrer toutes les possibilités du moteur.

La suite logique est évidente : reprendre le remplissage carnet avec le même état d’esprit. Garder la puissance interne, mais retirer le bruit visible.
