Exploration des tags et reprise de 2017

Deux anciens Digests composés à la main, les semaines 8 et 9 de 2017, rejoignent l’archive. L’explorateur de tags gagne un index alphabétique et les liens leurs favicons, tandis que les problèmes de cache sont résolus.

Publication native

Préparer le post LinkedIn

Le compteur inclut le texte, les hashtags et l’adresse partagée.

Demandes et échanges

Cette section est reconstituée depuis les commits et leurs diffs.

Le travail montre une alternance volontaire entre contenu et interface : réimporter une édition HTML, observer comment elle se consulte, puis améliorer la navigation avant de poursuivre l’import. Les correctifs successifs autour du cache indiquent que la mise en production réelle a servi de test, et qu’une simple modification du fichier source ne garantissait pas que le navigateur charge la nouvelle version.

Décisions

  • La restauration de 2017 se fait édition par édition, avec ses tags et sa source d’import conservée.
  • Les tags doivent être parcourables alphabétiquement, pas seulement filtrés par recherche.
  • Les ressources frontales personnalisées utilisent une stratégie de versionnement explicite pour traverser les caches.
  • Les favicons enrichissent le repérage visuel sans remplacer le titre ni la description éditoriale.

Réalisation

La semaine 8 de 2017 est ajoutée avec ses catégories et tags. Trois itérations améliorent ensuite l’explorateur : mise en forme, index alphabétique, puis versionnement du script.

La semaine 9 enrichit le catalogue de nouveaux sujets et introduit les favicons dans la page d’accueil, les archives, le flux et les pages de tags. Deux derniers correctifs stabilisent le cache busting.

Validation et déploiement

Les 17 exécutions GitHub Actions visibles pour cette journée sont réussies. Les quatre fusions de pull requests conservent une trace des itérations spécifiques à l’explorateur de tags.
