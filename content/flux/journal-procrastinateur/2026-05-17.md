## Le retour du PDF fine art

La veille, on avait acte que le tirage d'art devait conserver le fichier natif et produire un JSON recette. C'était sain pour protéger l'original, mais insuffisant pour l'atelier.

Aujourd'hui, le contrat a été corrige :

- `fine_art_print` produit aussi un **PDF prêt RIP** ;
- les fichiers natifs client restent intacts ;
- le JSON reste la recette et la source de vérité ;
- le PDF devient l'artefact primaire du paquet atelier pour figer format, bord blanc, cadrage, quantité et rendu attendu.

Le flux PDF a été rebranche dans les routes, le payload `pdf_forge`, le worker et le renderer. Le rendu fine art utilise le format physique de chaque tirage, repete les pages selon la quantité et reutilise les mêmes aides shared que l'UI.

La question des profils ICC est maintenant explicite : si le profil source manque, on documente le fallback sRGB et on force une vigilance atelier.

## Lisibilité client et confiance photo

Le gros sujet psychologique du jour a été la qualité percue des photos.

Dans `Mes photos`, le libellé texte trop brutal a été remplace par des indicateurs plus discrets et plus utiles :

- pastille verte : `Optimal` ;
- pastille orange : `Moyen` ;
- pastille rouge : `Faible`.

Dans la prévisualisation, on affiche maintenant deux dimensions simples :

- `Optimal a 240 ppp : 42 x 32 cm`
- `Format maximum a 180 ppp : 56 x 42 cm`

Le but est important : ne pas effrayer le client avec un verdict sec. Il doit comprendre jusqu’où il peut raisonnablement aller. Le 240 ppp reste l'idéal, le 180 ppp devient la limite conseillee, plus proche de la vraie question client : "je peux l'imprimer a quelle taille ?".

On a aussi corrige les noms de fichiers trop longs pour éviter les ascenseurs horizontaux, et renomme l'action principale en **Créer un tirage**, beaucoup plus claire que `Ajouter au dossier`.

## Mode confort

Une discussion presque philosophique a ouvert un vrai sujet : comment KEREDIT est vu par des clients qui n'ont pas les mêmes yeux que nous.

Le résultat est un **Mode confort** :

- activable depuis le header ;
- persiste en `localStorage` ;
- applique via `data-visual-comfort="comfort"` ;
- palette plus claire, gris ardoise doux, contrastes renforces ;
- photos et papier jamais recolores ;
- indicateurs qualité toujours colores, mais moins dependants de la couleur seule.

Ce n'est pas une version basse vision complète. C'est une première couche de confort visuel et d'accessibilité, utile aussi pour les clients qui n'aiment pas les interfaces sombres.

## Bibliothèque Mes photos

La bibliothèque a pris une autre dimension.

Elle est plus large, plus respirante, avec une toolbar evolutive :

- recherche raccourcie ;
- tri ;
- date ;
- lieu ;
- qualité ;
- usage ;
- densité de grille ;
- chips actifs ;
- dossiers intelligents prepares.

Le tri conseille devient le mode par défaut : prise de vue récente si disponible, sinon upload récent, avec favoris et photos non utilisées légèrement favorises.

Les filtres couvrent maintenant :

- date de prise de vue ou upload ;
- lieu, avec ou sans GPS ;
- qualité ;
- usage projet/page ;
- favoris ;
- non utilisées.

On a aussi prepare les futurs mini-dossiers thematiques. En v1 ils sont intelligents et non editables : toutes les photos, favoris, non utilisées, avec lieu, derniers imports. Plus tard, ce sera une bonne base pour des dossiers client.

## Fine art : confirmations et petits garde-fous

Le studio fine art a encore reçu plusieurs ajustements :

- confirmation avant suppression d'un tirage dans la sidebar ;
- bouton de réinitialisation dans la carte Image ;
- libellés `Largeur` et `Hauteur` dans la carte Format ;
- bouton d'echange largeur/hauteur ;
- informations de format cohérentes avec la bibliothèque photo ;
- formats standards rationalises ;
- format feuille minimum bloque a A4 ;
- largeur max respectee a 109 cm ;
- correction des filets noirs parasites autour de l'image.

La logique produit se precise : on imprime une feuille fine art, pas un petit 10 x 15 pigmentaire. Une image peut être petite dans un A4, mais la feuille fine art ne doit pas descendre sous ce minimum.

## Rail Pages et chrome éditeur

La fin de journée a beaucoup travaille le bas de l'éditeur.

Le rail `Pages` a été rendu plus lisible :

- `Voir les pages` devient `Voir le Carnet`, `Voir le Livre` ou `Voir la Carte` selon le produit ;
- zoom, plein écran et bug deviennent un onglet en bas à droite quand le rail est ouvert ;
- l'onglet ne saute plus visuellement entre les états ;
- les menus `Menu` et `Affichage` ne peuvent plus se chevaucher ;
- `Retour au backoffice` a été retire du menu, puisqu'il existe déjà en haut ;
- la barre de défilement native du rail est masquee au profit d'une barre tokenisee plus visible.

Ce dernier point a mérite une note durable : quand on veut dessiner un ascenseur cohérent avec le shell, il faut masquer la scrollbar native. Sinon on croit modifier le bon élément, mais le navigateur continue de montrer son propre artefact.

## Plan bêta

Un plan d'action bêta a été pose dans Plan d'action bêta KEREDIT - mai 2026.

La proposition est progressive :

1. **Vague 0** : 2 a 3 personnes en interne atelier.
2. **Vague 1** : 5 clients amis maximum.
3. **Vague 2** : 10 a 12 clients actifs, plafond dur a 20 comptes.
4. **Vague 3** : 25 a 40 clients seulement si la vague 2 tient.

Le bon signal attendu n'est pas l'absence totale de bug. Le bon signal est : le client comprend ce qu'il fait, peut sauvegarder et reprendre, OOBLIK peut régénérer/vérifier un PDF ou un paquet atelier, et aucun fichier sensible ne devient ambigu.

## Blocages et points ouverts

Points encore sensibles :

- `fine_art_print` doit être teste avec de vrais TIFF lourds et profils ICC varies ;
- le PDF fine art doit être relu sur des cas de bord blanc, quantité, adaptation et image entiere ;
- la bêta ne doit pas ouvrir trop large trop vite ;
- les smoke checks devraient aussi viser explicitement `https://ooblik.keredit.com/`, pas seulement l'ancien domaine ;
- la documentation doit continuer a distinguer le cœur KEREDIT, le CMS/WooCommerce et le futur service PDF externe.
