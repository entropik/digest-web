Day 118 – Securing access, discovering Kimi K3

Day 118 of the diary: the paid web PDF is conditional upon an actual paid Woo order; the GOF configuration is now set to the admin role; Better Auth sessions are revoked correctly; and the day begins with the discovery of Kimi K3.

Session timetable

  • Tool used: Codex, with Kimi Code CLI discovered and installed this morning
  • Main environment: Codex App on Mac, KEREDIT repositorydépôt local krampouz
  • Date covered: Monday 20 July 2026
  • Observation window: Kimi Code CLI installed at 09:54, followed by commits from 15:08:24 to 21:52:09 CEST
  • Minimum time observed: approximately 6 hours 44 minutes+ of commit window, plus the morning set-up
  • Merged branches: PRs #321, #322, #324, #325 and #327 into dev; version updated from 0.16.2 to 0.16.3
  • Main releases: paid web PDF entitlement, GOF admin configuration, shared clipart, email reset webhook, Better Auth sessions
  • Minimum cumulative time since the log began: approximately 779h00+ (772h16+ as at 19 July, plus 6h44+ observed)

Quick read

The day begins with a newcomer from the world of AI. Moonshot AI released Kimi K3 on 16 July: an open model with 2.8 trillion parameters using a mixture of experts, a context window of one million tokens, with full weights announced for 27 July. At 09:54, Kimi Code CLI is installed on the Mac with K3 as the default model. Claude Code launched the project, Codex has been running it since April; a third tool is now under observation.

The afternoon and evening are spent back in the workshop with one guiding principle: to close the doors that have been left ajar. Five pull requests tighten up the currency, configuration, sessions and emails, without touching the core of the editor.

Web PDFs are no longer free; they must be purchased

PR #321 is the centrepiece. The paid web PDF can no longer be enabled by the customer via the project’s options: entitlement is conditional upon a WooCommerce order that has actually been paid for.

The security hardening is methodical. An unknown order status is no longer treated as paid. Entitlement keys are frozen as soon as an order is linked, and the freeze decision is made under write protection. Rights already granted via authorised paths are preserved, including for refresh, rotation and GOF rendering, and legacy orders without a status remain accepted so as not to break existing functionality.

The GOF configuration belongs to the admin

PR #322 restricts GOF configuration to the ‘admin’ role. URLs are validated; the URL policy also applies to pairing; and the ‘Auto GOF’ toggle is hidden from the ‘editor’ role. A workshop editor no longer has access to the settings that determine production.

The details that matter

Three shorter fixes round off the day. PR #324 preserves the colours of shared clipart, which were being lost during public viewing. PR #325 secures reset logs and hard-codes the email webhook variables, with production secrets set in the test. PR #327 revokes the Better Auth session on logout, restricts the catch-all `auth-v2`, limits revocation to the current session and properly expires the ` __Secure-`-prefixed cookie in production.

A day of fine-tuning

Nothing spectacular on screen, but it’s the sort of day that makes the beta worth defending: the money follows the order, the configuration follows the role, the session follows the logout. And this morning, almost in passing, the workshop has undergone a transformation: a new Frontier open-weight model has arrived, and its CLI is already installed on the machine.
