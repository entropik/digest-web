Day 121 – Review, consolidate, publish

Day 121 of the log: after six days without a commit, KEREDIT consolidates the load, email, dependencies, shopping basket, connector and GOF acceptance test, then restores the VPS to a verified release.

Quick read

The repository remained quiet from 24 to 29 July. On the 30th, the return did not take the form of a major new feature: it pieced things together, restored useful logs and put a clean release branch back onto the VPS.

It’s a busy day, at times thankless. It involves handling the workload, emails, dependencies, customer messages, the WordPress shop basket and the workshop revenue. Yet its guiding principle is clear: to pick up where we left off after the break without leaving multiple competing versions in the branches, releases or tools.

Recovering what might otherwise have been left behind

Two rescue branches preserve an editor load campaign and a snapshot prior to the IPTC project. The ‘dev’ branch then recovers a realistic editor session scenario, the log for Days 117 to 119, and the map of recent releases.

This consolidation is not merely a Git tidy-up. It prevents load tests, editorial decisions or fixes that have already been reviewed from becoming trapped in a forgotten branch upon returning from holiday.

Email and dependencies are included in the contract

The WordPress connector gains an authenticated REST endpoint to send KEREDIT reset emails. The release metadata and the manifest checksum have been aligned. At the same time, four vulnerabilities high in the CI audit gate have been fixed, and historical transitive dependencies have been refreshed without breaking the toolchains still in use.

The objective is less visible than a new screen, but essential for the beta: the user must receive their email, and the pipeline that produces it must remain deployable without any known security vulnerabilities.

Explaining quotas instead of speaking like a server

Upload quota errors are rewritten for the end user: the cause and possible action are stated simply, without infrastructure jargon. The local composer also publishes services on the IPv4 and IPv6 loopbacks so that localhost does not become unpredictable depending on the machine.

The package thus combines two forms of reliability: an error must be understood by the client, and the same local environment must respond consistently on Macs as well as on previous machines.

Resuming a project without introducing unintended changes

The shopping basket recovery feature corrects an unintended version update. Opening a project should no longer trigger an autosave, a new version or a re-validation by the sales team if the price, format, quantity and options remain unchanged. The connector also correctly encodes empty dictionaries for simple products, and release archives become reproducible.

The customer’s action once again matches what they intend to do: resume and view, not silently modify the basket.

The acceptance test must never deliver to Accurio

Since GOF 0.8.0, the Accurio handover has been separated from the rendering. KEREDIT has therefore removed the old contract capture from its v2 acceptance test and now proves the absence of a live handover instead of waiting for a pseudo-verdict of ‘not sent’. Automated validation can test the entire workflow without requiring a delivery client or risking an actual transmission.

The release is finalised on KEREDIT 0.16.16; check on the VPS that the SHA merges. After a turbulent week, this is the right way to resume: fewer promises, a single line dev, and a verifiable source.
