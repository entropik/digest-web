Day 137 – Tidying up the Claude era without losing our memories

Day 137 of the diary: Claude’s old commands and skill copies have been removed, whilst his last two useful rules have been added to AGENTS.md.

Session timetables

  • Tool used: Codex
  • Main environment: VS Code WSL, Codex plugin on the left, code in the centre, Codex terminal on the right
  • Date covered: Wednesday 26 August 2026
  • Branch observed: dev, three documentation and clean-up commits
  • Time window selected for the minimum: 18:27 – 19:12 CEST
  • Minimum time observed: approximately 0h45+
  • Release status: no new releases or runtime deployments observed
  • Main traces: 4c31d50a, 9c8e4eba and 830fa929; removal of .claude, copies of .github/skills, references to slash commands and CLAUDE.md
  • Minimum cumulative time since the start of the log: approximately 885h20+ (884h35+ as at 25 August, + 0h45+ today)

Quick read

The session lasts less than an hour and removes over a hundred thousand lines. This contrast does not indicate a rewrite of the product: it indicates the removal of duplicate tools and instructions that have become obsolete. The slash commands from Claude Code are no longer in use; several snapshots of the impeccable skill duplicate source code managed elsewhere; and CLAUDE.md describes a CI as well as structural files that no longer correspond to the repository.

The clean-up brings an era to a close without denying its achievements. Before removing the last file, two rules that still hold true are saved in frontend/AGENTS.md: first, fill in the empty photo blocks and keep all the snapping logic within its canonical module.

Remove duplicates that create false context

The directories .claude/commands, .claude/skills and the copies at .github/skills are removed. They contained slash commands and bulky snapshots of skills that were no longer the current sources. Personal workflows now reside in locations managed by agents, whilst repository-specific instructions remain at .agents/skills and in the AGENTS.md files.

This removal reduces a real risk: an agent might have read an outdated copy, followed a command that no longer exists, or believed that a duplicate script was still being maintained. The number of lines removed is staggering, but the decision remains straightforward: a single, up-to-date source is better than several executable archives that are all similar.

CLAUDE.md should no longer compete with AGENTS.md

The latest commit removes CLAUDE.md. The file repeated part of the root instructions, including a CI statement that is now incorrect and an out-of-date list of important files. README.md, docs/HOME.md and the onboarding guide will therefore no longer refer to it as a starting point.

The workstation recovery procedure has been rewritten to start from AGENTS.md, docs/HOME.md, docs/KEREDIT/START_HERE_CODEX.md and the command guide. The change does not merely involve replacing one agent’s name with another: it restores the current documentation hierarchy as the focus of the next session.

Two rules remain because they still protect the product

The first rule retained stipulates that an image insertion must first fill an empty block, or create a new block, without silently replacing a photo that is already in place. The second rule sets frontend/src/lib/snapping.ts as the sole source of magnetic alignment and reminds the user to call setCoords() after a change of position during object:moving.

These two sentences would have been lost with CLAUDE.md if the clean-up had been purely mechanical. Their migration illustrates the correct approach: remove the obsolete container, re-read its contents, then transfer each invariant that is still valid to the instruction file of the domain that applies it.

Status at the end of this post

The product remains unchanged and no runtime publications are claimed. KEREDIT ends the day with less concurrent context, a role realignment in line with WSL and Codex, and two frontend invariants placed in the correct location. The Claude Code era remains visible in the log history; it no longer features as a second technical authority in the current repository.
