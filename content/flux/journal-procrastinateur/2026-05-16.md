La journée a commence par une reprise après réparation du PC, puis par une remise a plat du cap. Le chantier `fine_art_print` était la bonne direction, mais l'écran initial ne racontait pas encore le bon produit : trop clair, trop latéral, trop décoratif, trop loin d'une table de tirage.
On a donc bascule vers une interface volontairement sombre, plus atelier, plus dense, avec le tirage actif au centre et les réglages essentiels sous la feuille.
- Temps cumulé minimal depuis le début du journal : **environ 278h+**

## Une vraie table sombre

La refonte UI a supprime les éléments qui brouillaient le parcours :

- plus de faux footer décoratif ;
- plus de grand panneau droit scrollable ;
- plus de vue in situ parasite ;
- une sidebar dossier compacte ;
- une table de tirage centrale sombre ;
- un dock bas pour `Format`, `Image`, `Papier / finition`, `Quantite`, `Atelier` ;
- un cartouche fichier horizontal, façon plan d'architecte.

La direction couleur a aussi été reprise plusieurs fois. Le premier sombre tirait trop vers le brun. On a fixe une base graphite / ardoise sombre, avec papier strictement blanc, textes gris chauds et accent bleu clair plutôt que bronze.

Le cartouche fichier a beaucoup aide à stabiliser l'écran : format, nom du fichier, matrice pixels, image tiree, dpi, agrandissement, mode, profil ICC, type et camera sont visibles sans ouvrir un détail cache.

## Format image-first

Le gros changement fonctionnel du jour est le format recommande depuis le fichier.

à l'import, l'assistant calcule le format idéal a **240 dpi** :

- `largeur_cm = width_px / 240 * 2.54`
- `hauteur_cm = height_px / 240 * 2.54`
- arrondi à un chiffre après la virgule

L'objectif produit est simple : partir de l'image client, pas d'un format arbitraire `40 x 60`.

On a aussi repris les formats standards :

- contrainte machine : rouleaux **17, 24 et 44 pouces** ;
- largeur imprimable max : **109 cm** après marge technique ;
- DIN remis en tête avec `A5`, `A4`, `A3`, `A3+`, `A2`, `A1`, `A0` ;
- formats courants en deuxième ;
- ratios, carres et panoramiques ensuite.

La modale des formats a été agrandie et passe en 4 colonnes sur grand écran. Le bouton information sert maintenant a rassurer, expliquer le calcul et offrir la grille complète.

## Image, bord blanc et manipulation

La carte `Image` a été le vrai cœur de la journée.

On a introduit la distinction entre :

- `Image entiere` : préserve tout le fichier, avec marges eventuelles ;
- `Adapter` : couvre le bloc, donc peut recadrer légèrement ;
- `Bord blanc` : impose un bord uniforme autour de l'image ;
- bloc image libre : taille image modifiable dans la feuille.

On a aussi ajoute :

- champs largeur/hauteur image avec steppers ;
- bord blanc en cm, par pas de `0.5 cm` ;
- zoom d'adaptation seulement quand il est pertinent ;
- déplacement souris sur le tirage ;
- bouton `Centrer` ;
- poignée de déplacement plus discrete.

Plusieurs régressions sont sorties en test réel :

- en `Bord blanc`, changer la largeur sortait visuellement en `Adapter`, parce que le mode était detecte uniquement par marges egales ;
- les champs numériques reformataient trop tôt et empechaient de saisir `20` normalement ;
- la croix de déplacement suivait parfois le mauvais centre ;
- les contours de preview pouvaient ressembler a des filets noirs ou verts imprimes ;
- après duplication, le diagnostic pouvait afficher `Fichier en analyse` alors que l'image était visible.

Ces points ont été corriges cote UI, et la règle générale est maintenant posée pour la suite : un champ numérique contrôle ne doit jamais arrondir, formatter ou clamper a chaque frappe. Il doit garder une valeur texte locale et normaliser seulement au blur, a Enter, au submit ou via les boutons `- / +`.

## Le piège du format au rechargement

Un blocage important a été trouve sur `page.surface`.

Le backend conservait bien le format propre au tirage, mais au chargement frontend, `editorStore.loadProject()` supprimait les `surface` de page pour tous les produits hors `book`. Pour `fine_art_print`, c'était une régression structurelle : chaque page est justement un tirage avec son propre format.

La correction garde maintenant les `page.surface` pour `fine_art_print`.

On a aussi nettoye un autre piège : les formats standards choisis depuis l'UI ne doivent pas persister des champs internes comme `group`, `ratioDistance` ou `sizeDistance`. La surface persistée doit rester un format produit simple : `label`, `width_mm`, `height_mm`.

## Le doute PDF

La décision de production a bouge dans la journée.

Au départ, on avait acte : **pas de PDF**, uniquement fichier natif client + JSON récapitulatif. C'était juste pour protéger l'original et éviter de refaire un renderer trop tôt.

Mais en fin de session, le doute métier est devenu clair : pour reproduire exactement un bord blanc, un cadrage, un format de feuille et une position, le JSON seul est trop abstrait pour l'atelier.

La nouvelle cible est donc :

- **original client intact** : TIFF/JPEG jamais ecrase ;
- **JSON commande** : recette structuree, modifiable, auditable ;
- **PDF atelier dérive** : preuve visuelle et fichier de rendu exact du tirage demande.

Le PDF ne remplace pas le JSON et ne devient pas la source de vérité. Il est une sortie derivee depuis le fichier natif et la recette.

## État pour la suite

Le chantier est beaucoup plus lisible qu'hier, mais il reste sensible.

Priorités suivantes :

1. formaliser le contrat PDF atelier dérive pour `fine_art_print` sans écraser les fichiers natifs ;
2. verrouiller les tests autour de `page.surface`, `formatSource`, bord blanc et duplication ;
3. stabiliser les vieux projets de test pollues par les anciennes surfaces standards ;
4. vérifier le comportement sur TIFF réels, profils ICC, grandes images et formats panoramiques ;
5. définir le paquet atelier final : fichiers natifs, JSON recette, PDF dérive, récap lisible.

La journée a été nerveuse parce que l'UI touchait à une zone très métier : le client doit comprendre ce qu'il commande, et l'atelier doit pouvoir le refaire sans deviner. On a casse puis repare plusieurs fois, mais c'était utile. Le produit commence à dire quelque chose de plus juste : une table de tirage, pas un formulaire.
