## Lecture courte

Après la pause du mardi, la soirée du mercredi condense huit pull requests
KEREDIT et deux pull requests GOF en un peu moins de sept heures. Le fil
directeur : ce que l'utilisateur voit au moment de partager ou de commander
doit être exactement ce que la production croit.

En parallèle, ce journal change de main. Les billets de rattrapage des jours
117 à 119 sont rédigés avec Kimi Code CLI, installé lundi matin : première
vraie session de l'outil sur le dépôt, trois jours après la sortie de Kimi K3.

## Ne jamais croire une commande sur parole

La PR #328 durcit la chaîne WooCommerce. Les commandes KEREDIT sont
revérifiées via l'API REST Woo avant production, et un statut illisible est
refusé plutôt qu'interprété. Les articles de la commande relue sont validés
eux aussi, et leur rôle — produit principal ou add-on — est comparé à ce que
le webhook avait annoncé. La commande d'origine n'est plus une vérité figée :
elle est relue au moment où elle engage l'atelier.

## Le partage public devient un vrai aboutissement

Trois PR se suivent sur le lecteur public. La #329 permet de télécharger le
PDF web GOF v2 depuis le partage, avec un lecteur de statut de confiance
injecté dans le test de flux Woo et des dépendances vulnérables corrigées au
passage. La #330 supprime l'onglet blanc qui s'ouvrait avec le lien public.
La #332 empêche l'ouverture du lien de relancer un rendu GOF : consulter un
partage ne doit jamais ressembler à une commande.

## Deux gardes-fous d'infrastructure

La PR #333 réécrit le callback OAuth Google Photos : plus d'injection de code
dans la page de retour, et une réponse compatible avec la Content Security
Policy. La connexion au compte photo du client reste fluide, mais la fenêtre
de retour ne peut plus servir de vecteur de script.

La PR #335 ferme le pipeline d'assets aux images de plus de 100 mégapixels :
le rejet a lieu avant décodage, passe par le rejet métier nominal, refuse
proprement les catalogues trop grands au confirm d'upload, et la limite
`ASSET_PIPELINE_MAX_INPUT_PIXELS` est passée jusque dans le compose VPS, sans
doublon dans le worker.

## La soirée n'était pas finie

La première version de ce billet s'arretait ici, à 19:06. Git montre pourtant
une seconde moitié de session plus importante encore que la première.

KEREDIT apprend d'abord a régénérer une Production v2 existante sans perdre ses
familles. Les bindings suivent désormais une itération de rendu explicite, le
téléchargement du PDF web prend l'artefact courant et les replays WooCommerce
reconnaissent ce nouveau lignage. Le polling reste en lecture seule : consulter
l'état de GOF ne doit jamais réécrire la production qu'il observe.

## Les templates sont verrouilles aussi sur le serveur

En parallèle, une longue série de corrections durcit les variantes exactes de
template. Le changement de format préserve la géométrie prouvée, les permissions
et l'identité visuelle sont comparees à une baseline canonique, les deplacements
inter-pages sont controles et les ecritures tardives sont cloturees sous verrou.

Le point produit est simple : un client peut modifier ce que le template lui
autorise, pas reconstruire silencieusement le contrat depuis un payload plus
permissif.

## GOF 0.8.0 rend les itérations immuables

GOF commence la séquence en `0.7.3` avec l'auto-remise Accurio bornee par une
activation horodatee. Puis la PR #85 introduit `0.8.0` et les itérations de
rendu Production v2.

Une régénération cree maintenant un candidat immuable. Le PDF courant reste
disponible jusqu'a sa promotion atomique, les incidents et remises restent
attaches a leur itération, et une ancienne itération ne peut plus initier une
action Accurio. Le rendu et la livraison deviennent deux décisions distinctes,
avec un historique exploitable au lieu d'un fichier courant ecrase.

## Kimi tient le journal

Dernière donnée du jour, et pas la moins importante pour ce journal : le
rattrapage documentaire lui-même est fait avec Kimi Code CLI. L'outil lit le
dépôt, retrouve les preuves dans Git, suit la procédure du skill blog et
produit les billets 117, 118 et 119 dans le modèle habituel. Claude Code a
lancé l'aventure, Codex l'a portée jusqu'ici ; Kimi K3 fait ses premières
armes sur la mémoire du projet, et c'est ce journal qui s'en souviendra.
