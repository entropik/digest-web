Day 135 – Measuring sovereignty, closing blind spots

Day 135 of the log: OVH measures have been brought into line, the keys have been secured, an incident relating to object ownership has been resolved, and the KEREDIT-GOF workflows have become portable.

Session timetable

  • Software used: Codex
  • Primary environment: Mac, KEREDIT dépôt local krampouz, GOF dépôt local gof, Hetzner Germany VPS and OVH 3-AZ Paris
  • Date covered: Monday 24 August 2026
  • Main branches: chore/k6-storage-provider-metrics, codex/portable-workflows and GOF branches of PRs #92/#93
  • Time window selected for the minimum: 10:56 – 19:30 CEST, cross-checked KEREDIT and GOF tracks
  • Minimum duration observed: approximately 8h34+
  • Release status: KEREDIT PRs #455/#456/#475 and GOF PRs #92/#93 merged into dev; 0.22.9 release deployed to production on the same day
  • Main changes: metric provider, k6 fixes, OVH key rotation, orphaned objects incident resolved and logged, 203/EXEC timer fix, portable workflows and purge of test data
  • Minimum cumulative time since the start of the log: approximately 874h47+ (866h13+ as at 23 August, +8h34+ today)

Quick read

The switchover is complete; the day is spent ensuring the evidence is preserved for the long term. The load reports finally distinguish the PUT time at the provider’s end, the Google Photos retries are consistent, and the log clearly documents what has been measured and what has not. At the same time, the rotation of OVH keys reveals the ACL model of the buckets, leading to the removal of the former POC user — and this deletion triggers a real incident: the objects become orphaned and unreadable for a few hours, before a step-by-step repair is carried out.

Client data sovereignty therefore does not depend solely on two countries on a map. It depends on the ability to explain where the data resides, who can access it, how the service is measured and how to roll back changes.

Don’t let a green benchmark become a legend

The k6 scripts isolate storage_put_duration, adhere to Retry-After and report n/a when a provider metric does not exist. The Google Photos scenario makes four consistent attempts and returns the last useful response. The report also specifies that the failed_count metric was not available during the 23 August campaign.

This honesty counts: OVH is significantly faster than R2 in the measurements carried out, but only the observations actually collected are attributed to the switch. The benefit of being based in France does not need a embellished figure to be significant.

The key points remind us that location alone is not enough

During the rotation, a new OVH S3 user receives ‘403 AccessDenied’ errors even though their keys are valid. The bucket belongs to the user who created it, and this service does not provide the expected bucket policies: the new user must be added to the ACL without revoking the owner’s grant.

The procedure is applied to krampouz-assets-prod, then the former POC user is revoked once the new keys have been propagated to KEREDIT and GOF. The runbook retains this specific provision for subsequent rotations. The storage is located in France; access to it must remain explicitly governed.

Deleting a user leaves their objects orphaned

The rest of the rotation proves that caution was justified, albeit painfully. The former POC user is deleted from the console by late morning, once the new keys have been verified. A few hours later, not a single thumbnail or image is displayed in the editor: each S3 object belongs to the user who created it, and deleting that user renders its 22,000 objects unreadable (403 AccessDenied on GET/HEAD, although the listing still works). The ACL for the successor’s bucket FULL_CONTROL does not change this, and PutObjectAcl is denied to non-owners.

The fix involves the R2 source, which has been kept as a fallback: a complete recursive copy of mc cp --recursive (rather than mc mirror --overwrite, which skips identical objects) to rewrite the 78 GB and transfer ownership to the new user. Variant generation jobs that fail during the maintenance window must be restarted via an explicit retry call, as BullMQ deduplication on jobId ignores simple re-adds. The publisher returned to normal operation that same evening, and the corrupted test data (12,295 assets, 3,016 projects, 13,112 orphaned objects) was purged correctly.

Two rules were added to the runbook to ensure no customer experiences this: never delete an S3 user before reassigning ownership of their objects, and never purge the source of truth before verifying readability by the successor. The R2 fallback, intended merely as a safety net, was used the very next day after the switchover.

KEREDIT and GOF maintain a common approach

The workflows for development, review, implementation and deployment are made portable between repositories. GOF now checks the origin of a release more strictly, and its CI no longer builds a runtime image for a purely documentary merge whilst monitoring the Docker context rules.

A patch also restores the executable bit on acceptance test scripts following a systemd failure (203/EXEC). This operational detail ties in with the main thread: a European infrastructure is only of value if the checks that validate it can actually be executed.

Status at the end of this post

KEREDIT and GOF use OVH 3-AZ Paris for production storage, with the application VPS in Germany and R2 still available for rollback during the grace period. The ‘0.22.9’ release is live, the campaigns are running smoothly, the measurement thresholds are documented, the orphaned objects incident has been resolved and its rules have been recorded in the runbook. What remains is long-term monitoring, a second copy with another European provider and, only at a later stage, the irrevocable decision to decommission R2.
