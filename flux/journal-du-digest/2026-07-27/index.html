Journal du Digest

/index 27 juillet 2026

Administration et curation depuis Chrome

Le Digest passe d’une archive statique à un système de curation propriétaire avec administration, extension Chrome et publication atomique. Quinze commits et trente exécutions GitHub Actions réussies installent ce nouveau parcours.

Publication native

Préparer le post LinkedIn

Le compteur inclut le texte, les hashtags et l’adresse partagée.

Demandes et échanges

Les décisions suivantes ont été précisées explicitement dans la conversation :

  • déclenchement par l’icône Chrome et par un raccourci configurable.
  • formulaire compact prérempli et enregistrement rapide.
  • file privée permettant de sélectionner 10, 20 liens ou davantage.
  • publication d’un seul Digest pour le lot choisi.
  • usage par le seul propriétaire.
  • titre, catégorie, résumé et au moins un tag obligatoires à la publication.
  • date et titre proposés, introduction et description SEO éditables.
  • catégories puis titres triés alphabétiquement.
  • blocage si la date possède déjà un Digest.
  • métadonnées du Digest modifiables après publication.
  • suivi jusqu’à la validation GitHub Actions et la présence en production.
  • diffusion Chrome Web Store non répertoriée avec mises à jour automatiques.

La préparation du Web Store a ensuite porté sur l’identifiant stable de l’extension, le package, l’icône, les captures, la description, les justifications de permissions et la politique de confidentialité. La soumission est passée à l’état « en attente d’examen ».

Décisions

  • Hugo reste le site public. admin-service est l’unique backend.
  • L’extension ne parle jamais directement à GitHub.
  • Les brouillons incomplets sont permis, mais leur publication est bloquée.
  • La taxonomie vient exclusivement du catalogue existant.
  • Les URL privées, locales, authentifiées ou sensibles sont refusées.
  • Un doublon actif rouvre le brouillon. Un lien publié renvoie vers sa fiche d’administration.
  • Le catalogue et l’archive sont écrits dans un seul commit.
  • La publication est idempotente et retente une fois après conflit GitHub.
  • La note privée et la sélection ne quittent jamais l’espace privé.
  • Le serveur accepte seulement l’origine exacte de l’extension Web Store.
  • L’extension utilise Manifest V3, WXT et TypeScript sans React.

Réalisation

Consultation et mémoire

La semaine 15 de 2017 est ajoutée. La page d’accueil reçoit les filtres par date, l’accès aléatoire et les favoris. La navigation et les archives sont améliorées. Les liens morts peuvent pointer vers une capture Wayback tout en préservant leur URL d’origine.

Administration

Le service propriétaire ajoute Better Auth, la GitHub App, la modification de visibilité et l’interface /admin. Le retrait public est volontairement discret et séparé des actions ordinaires. Un conflit de port est corrigé avant le déploiement.

Curation et publication

SQLite reçoit les brouillons et publications. Les API couvrent les options de taxonomie, le CRUD, l’aperçu, la publication, les liens et les éditions.

La publication valide de nouveau toutes les données côté serveur, impose l’unicité de la date, crée des UUID stables, écrit deux fichiers dans un commit et suit les workflows associés au SHA. Des fixtures communes alignent la normalisation TypeScript et Python.

Extension et Chrome Web Store

L’extension capture après action explicite l’URL, le titre, le canonical, la meta description et la sélection. Les permissions sont limitées à activeTab, scripting et https://digest.ooblik.com/*.

L’identifiant Web Store retenu est nlejcccmpbajpoaknlecegkpgdegiflf. Les icônes et visuels promotionnels sont générés et archivés dans browser-extension/store-assets/. La page publique /confidentialite/ décrit la collecte volontaire, l’usage limité et les permissions. Son lien est placé dans le pied de page après « Admin ».

Exploitation

Deux correctifs successifs renforcent le redémarrage PM2 lors du changement de release ou lorsqu’un processus précédemment arrêté doit être recréé.

Validation et déploiement

Avant la soumission, les tests et typages de l’administration et de l’extension passent, ainsi que les contrôles du catalogue et le build Hugo. Le catalogue compte alors 3 979 liens cohérents et 835 éditions.

Les workflows Validate et Deploy production sont suivis pour les changements de l’extension, de la confidentialité et du pied de page. Le résultat public est contrôlé après la relève CloudPanel.

La soumission Chrome Web Store est désormais en attente d’examen. Google indique que la plupart des examens prennent quelques jours, mais qu’ils peuvent durer plusieurs semaines. Un rappel est prévu le 17 août 2026 pour contacter le support si le statut n’a pas évolué.

Prolongement Firefox

Le 2 septembre 2026, le même socle est devenu une extension Firefox officielle et signée. Le billet La curation traverse Firefox documente l’adaptation Manifest V2, la validation AMO, l’installation de la version 1.5.0 et son contrôle dans le navigateur réel.
