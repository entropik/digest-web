Day 132 – Preparing for sovereignty without compromising uploads

Day 132 of the diary: KEREDIT tightens up pre-signed uploads ahead of the switch to OVH and releases version 0.22.6.

Session timetable

  • Tool used: Codex
  • Main environment: Mac, multiple KEREDIT worktrees, GitHub Actions and Hetzner VPS in Germany
  • Date covered: Friday 21 August 2026
  • Main branches: feat/presigned-upload-retry, codex/vrifier-ltat-de-la-branche and workflow branches, all merged into dev
  • Time window selected for the minimum: 11:05 – 12:46 CEST
  • Minimum duration observed: approximately 1h41+
  • Version released: 0.22.6, release 20f0f8c3
  • Main traces: 22 non-merge commits, PRs #445 to #447, upload retry and hardening of development workflows
  • Minimum cumulative time since the start of the log: approximately 847h38+ (845h57+ as at 20 August, plus 1h41+ today)

Quick read

The decision to use OVH has been made, but a preference for sovereignty is not enough to secure customers’ photos. Before switching providers, KEREDIT is hardening the most exposed operation: direct uploads from the browser to object storage. Pre-signed uploads now include a retry mechanism with exponential backoff, and the mobile flow has been integrated into the same sharing module as the rest of the frontend.

This step is less spectacular than copying a bucket. Yet it is essential to ensure that the switch from a US provider to a French storage service does not turn a laudable ambition into a step backwards for customers.

A European architecture must also keep outages brief

The future path is becoming clear: the application runs on the Hetzner VPS in Germany and client objects must reside with OVH in France. This European setup reduces the main storage’s exposure to the Cloud Act, but it does not eliminate network errors, 429 errors or 5xx errors from a provider.

The helper presignedUpload.ts therefore handles transient errors with an increasing wait time. The Codex review adjusts the backoff exponent, then verifies that the mobile path correctly uses this shared contract. The change is covered by unit tests and documented in BIBLIOTHEQUE.md.

Making the method as reliable as the product

The second part of the session focuses on Codex workflows and contextual documentation. Audits are now better at detecting skill snapshots, old directories that have been removed and renamed paths. Detached worktrees are verified against their actual base, and managed copies can no longer be overwritten silently.

This work may seem tangential to storage. Yet it serves the same purpose: a production switchover between KEREDIT and GOF requires knowing exactly which branch, which version and which procedure is currently in effect.

End-of-day status

KEREDIT 0.22.6 is delivered with the upload retry feature. No production objects have yet changed provider. The target remains OVH Standard 3-AZ Paris, R2 remains the active source, and the next step must be a reversible, measured and shared copy for both KEREDIT and GOF.
