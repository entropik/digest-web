Jour 137 - Ranger l'ère Claude sans perdre la mémoire

Jour 137 du journal : les anciennes commandes et copies de skills Claude sont retirées, tandis que leurs deux dernières règles utiles rejoignent AGENTS.md.

Horaires de session

  • Agent utilisé : Codex
  • Environnement principal : VS Code WSL, plugin Codex à gauche, code au centre, terminal Codex à droite
  • Date couverte : mercredi 26 août 2026
  • Branche observée : dev, trois commits documentaires et de nettoyage
  • Fenêtre retenue pour le minimum : 18:27 -> 19:12 CEST
  • Temps minimal observé : environ 0h45+
  • État de publication : aucune nouvelle release ni aucun déploiement runtime observés
  • Traces principales : 4c31d50a, 9c8e4eba et 830fa929 ; retrait de .claude, des copies .github/skills, des références aux slash commands et de CLAUDE.md
  • Temps cumulé :885h20+ (884h35+ au 25 août, + 0h45+ ce jour)

Lecture courte

La session dure moins d’une heure et retire plus de cent mille lignes. Ce contraste ne raconte pas une réécriture du produit : il raconte la suppression de copies d’outils et d’instructions devenues obsolètes. Les slash commands de Claude Code ne sont plus utilisées, plusieurs snapshots de la skill impeccable dupliquent des sources gérées ailleurs et CLAUDE.md décrit une CI ainsi que des fichiers structurants qui ne correspondent plus au dépôt.

Le nettoyage ferme une époque sans nier ce qu’elle a apporté. Avant de retirer le dernier fichier, deux règles encore justes sont sauvées dans frontend/AGENTS.md : remplir d’abord les blocs photo vides et garder toute la logique de snapping dans son module canonique.

Supprimer les doubles qui fabriquent du faux contexte

Les répertoires .claude/commands, .claude/skills et les copies .github/skills sont retirés. Ils contenaient des commandes slash et des instantanés volumineux de skills qui n’étaient plus les sources courantes. Les workflows personnels vivent désormais dans les emplacements gérés par les agents, tandis que les instructions propres au dépôt restent sous .agents/skills et dans les fichiers AGENTS.md.

Cette suppression réduit un risque concret : un agent pouvait lire une copie ancienne, suivre une commande qui n’existe plus ou croire qu’un script duplique était encore maintenu. Le nombre de lignes retirées est spectaculaire, mais la décision reste simple : une seule source actuelle vaut mieux que plusieurs archives exécutables qui se ressemblent.

CLAUDE.md ne doit plus concurrencer AGENTS.md

Le dernier commit retire CLAUDE.md. Le fichier répétait une partie des instructions racine avec une affirmation CI devenue fausse et une liste de fichiers importants périmée. README.md, docs/HOME.md et le guide de reprise cessent donc de le présenter comme une porte d’entrée.

La reprise de poste est reformulée pour partir de AGENTS.md, docs/HOME.md, docs/KEREDIT/START_HERE_CODEX.md et du guide des commandes. Le changement ne consiste pas seulement a remplacer le nom d’un agent par un autre : il remet la hiérarchie documentaire actuelle au centre de la prochaine session.

Deux règles survivent parce qu’elles protègent encore le produit

La première règle conservée impose qu’une insertion d’image remplisse d’abord un bloc vide, ou crée un nouveau bloc, sans remplacer silencieusement une photo déjà posée. La seconde fixe frontend/src/lib/snapping.ts comme source unique de l’alignement magnétique et rappelle d’appeler setCoords() après une mutation de position pendant object:moving.

Ces deux phrases auraient été perdues avec CLAUDE.md si le nettoyage avait été seulement mécanique. Leur migration montre le bon critère : supprimer le support obsolète, relire son contenu, puis porter chaque invariant encore valide dans le fichier d’instructions du domaine qui l’applique.

État en fin de billet

Le produit ne change pas et aucune publication runtime n’est revendiquée. KEREDIT termine la journée avec moins de contexte concurrent, une reprise de poste alignée sur WSL et Codex, et deux invariants frontend places au bon endroit. L’ère Claude Code reste visible dans l’histoire du journal ; elle ne reste plus chargée comme une seconde autorité technique dans le dépôt courant.
